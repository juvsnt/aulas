O cenário e como fazer

Uma loja on-line tem um único item no estoque. Dois clientes, Ana e Beto, clicam em “Comprar” quase no mesmo instante. Cada cliente será um processo separado do Linux (um programa em execução), e o estoque será um arquivo de texto que os dois leem e alteram: o estado compartilhado do sistema (slide 3).

Ana ──▶ estoque.txt ◀── Beto
O que este experimento é, e o que não é.

Os processos, o arquivo e a trava são reais, e tudo roda na sua conta, sem depender de colegas. Mas é uma única máquina, não uma rede. Na Parte 3, três arquivos fazem o papel de três servidores, e uma pausa (sleep) faz o papel do atraso da rede. Os conceitos (corrida, trava, cópias desatualizadas) são os mesmos de um sistema distribuído de verdade.

  • Abra o terminal e entre com sua conta.
  • Faça um passo por vez: clique em Copiar, cole no terminal, aperte Enter e confira o que aparece. Não digite o $: ele só indica onde começa o comando.
  • Tudo o que vem depois de # é um comentário: o terminal ignora.
  • Seus tempos e a ordem de algumas linhas podem ser diferentes dos exemplos. Registre sempre os seus.

Parte 1 · cerca de 20 min Medição real

O último item

Objetivo: ver dois clientes comprarem o mesmo item, que só existia uma vez.

Estado compartilhado
Informação que vários processos leem e alteram, e que representa a “verdade” do sistema naquele momento: um saldo, um assento, um estoque. slide 3
Concorrência
Vários processos independentes agindo ao mesmo tempo, sem uma fila natural que os organize. slide 4
Condição de corrida
Quando o resultado depende da ordem, imprevisível, em que as ações dos processos se intercalam. slide 6

Etapa A · Código

  1. Passo 1

    O que faz: cria a pasta sd-p06 dentro de atividades, na sua pasta pessoal (~). Se ela já existir, nada acontece.

  2. Passo 2
    cd ~/atividades/sd-p06   # entra na pasta da atividade

    O que faz: todas as partes acontecem nesta pasta.

  3. Passo 3

    O que faz: abre o editor nano num arquivo novo, compra.c.

  4. Passo 4 Copie o código abaixo e cole no nano (botão direito ou Ctrl+Shift+V):
    Código de compra.c · copie e cole no nano
    #include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <fcntl.h>
#include <unistd.h>
#include <sys/file.h>

int main(int argc, char *argv[]) {
    if (argc < 2) { printf("Uso: ./compra NOME [trava]\n"); return 1; }
    char *nome = argv[1];
    int trava = argc > 2 && strcmp(argv[2], "trava") == 0;
    int arq = open("estoque.txt", O_RDWR);
    if (arq < 0) { printf("Crie antes: echo 1 > estoque.txt\n"); return 1; }
    if (trava) {
        printf("[%s] pedi a trava\n", nome);
        flock(arq, LOCK_EX);               /* LOCK: espera a vez */
        printf("[%s] consegui a trava\n", nome);
    }
    char texto[16] = "";
    read(arq, texto, sizeof texto - 1);    /* 1. LER */
    int estoque = atoi(texto);
    printf("[%s] li estoque = %d\n", nome, estoque);
    usleep(500000);                        /* pausa de 0,5 s, de proposito */
    if (estoque > 0) {
        estoque = estoque - 1;             /* 2. CALCULAR */
        ftruncate(arq, 0);
        lseek(arq, 0, SEEK_SET);
        dprintf(arq, "%d\n", estoque);     /* 3. ESCREVER */
        printf("[%s] COMPREI! gravei estoque = %d\n", nome, estoque);
    } else {
        printf("[%s] compra negada: estoque esgotado\n", nome);
    }
    close(arq);                            /* UNLOCK: fechar solta a trava */
    return 0;
}
// fim do codigo
  5. Passo 5 Salve e saia: Ctrl+O, depois Enter, depois Ctrl+X.

Etapa C · Execução

  1. Passo 7

    O que faz: grava o número 1 no arquivo estoque.txt.

  2. Passo 8
    ./compra Ana   # Ana compra sozinha
    Saída esperada
    [Ana] li estoque = 1
[Ana] COMPREI! gravei estoque = 0

    Observe: com um cliente só, tudo certo: havia 1 item, Ana comprou, sobrou 0.

  3. Passo 9
    echo 1 > estoque.txt   # repõe o item
  4. Passo 10
    ./compra Ana & ./compra Beto & wait   # os dois clientes ao mesmo tempo

    O que faz: o & coloca cada programa para rodar em segundo plano, sem esperar o anterior terminar: Ana e Beto começam praticamente juntos. O wait espera os dois acabarem.

    Exemplo medido no LIAC

[2] 501785
[Ana] li estoque = 1
[Beto] li estoque = 1
[Ana] COMPREI! gravei estoque = 0
[Beto] COMPREI! gravei estoque = 0

    As linhas [1] 501784 e Concluído são avisos do terminal: o número do trabalho, o número do processo e o fim de cada programa em segundo plano. Os seus números serão outros, e um aviso Concluído pode aparecer só depois do próximo comando.

    Observe: os dois leram 1 antes de qualquer um gravar 0. Os dois compraram.

  5. Passo 11
    cat estoque.txt   # quanto sobrou no estoque?
    Saída esperada
    0

    Observe: o estoque diz 0, como se tudo estivesse certo, mas foram feitas duas vendas de um item que só existia uma vez. Compare com o slide 5.

Parte 2 · cerca de 10 min Medição real

A trava

Objetivo: usar uma trava para que LER-CALCULAR-ESCREVER aconteça como uma operação única, e medir quanto isso custa.

Consistência
Garantia de que o sistema só passa de um estado válido para outro estado válido. Vender 2 itens de um estoque de 1 não é válido. slide 7
Sincronização (trava, lock)
Mecanismo de coordenação: quem tem a trava faz a operação inteira; os outros esperam. A sequência vira atômica, isto é, indivisível. slide 8

O mesmo programa usa a trava quando você acrescenta a palavra trava. Ela é pedida com flock, uma chamada do Linux que trava um arquivo (linhas 14–18).

  1. Passo 1
    echo 1 > estoque.txt   # repõe o item
  2. Passo 2
    ./compra Ana trava & ./compra Beto trava & wait   # os dois, agora com trava
    Exemplo medido no LIAC
    [1] 502357
[2] 502358
[Ana] pedi a trava
[Ana] consegui a trava
[Ana] li estoque = 1
[Beto] pedi a trava
[Ana] COMPREI! gravei estoque = 0
[Beto] consegui a trava
[Beto] li estoque = 0
[1]-  Concluído              ./compra Ana trava
[Beto] compra negada: estoque esgotado
[2]+  Concluído              ./compra Beto trava

    Observe: quem pediu a trava em segundo lugar ficou parado entre “pedi” e “consegui” até o outro terminar. Quando leu, o estoque já era 0. Na sua tela, quem compra pode ser o Beto: depende de quem chega primeiro.

    Saída esperada
    0

Quanto custa a trava? O comando time mede o tempo total. Os parênteses juntam os dois clientes numa medição só; a saída dos programas é descartada (> /dev/null) para sobrar só o tempo.

  1. Passo 4
    echo 1 > estoque.txt   # repõe o item
  2. Passo 5
    time (./compra Ana & ./compra Beto & wait) > /dev/null   # mede SEM trava
    Exemplo medido no LIAC · os seus números mudam
    real    0m0,504s
user    0m0,001s
sys     0m0,002s
  3. Passo 6
    echo 1 > estoque.txt   # repõe o item
  4. Passo 7
    time (./compra Ana trava & ./compra Beto trava & wait) > /dev/null   # mede COM trava
    Exemplo medido no LIAC · os seus números mudam
    real    0m1,002s
user    0m0,002s
sys     0m0,001s

    Observe: o real (tempo de relógio). Sem trava, os dois esperam a pausa de 0,5 s juntos; com trava, um espera o outro, e as pausas se somam.

Parte 3 · cerca de 20 min Simulação local

Cópias atrasadas

Objetivo: ver o que acontece quando a mesma informação tem três cópias e uma atualização leva tempo para chegar a todas.

Um servidor único é um ponto único de falha: se ele cai, o sistema inteiro para. Por isso, sistemas grandes guardam cópias (réplicas) em vários servidores. Aqui, os arquivos replica_A.txt, replica_B.txt e replica_C.txt fazem o papel de três servidores, e uma pausa (sleep) faz o papel do atraso da rede. Não é rede de verdade: é um modelo para observar a ideia.

Replicação
Manter cópias da mesma informação em vários servidores, para tolerar falhas, ficar sempre disponível e atender mais perto do cliente. slide 9
Propagação
O tempo que uma atualização leva para chegar a todas as cópias. Nesse intervalo, partes do sistema mostram “verdades diferentes”. slide 10
Consistência forte × eventual
Forte: todos veem o mesmo valor imediatamente, ao custo de esperar. Eventual: responde rápido, as cópias divergem por um tempo e depois convergem. slide 11

Etapa A · Script

  1. Passo 1
    nano -l replicas.sh   # abre o nano num arquivo novo

    O que faz: desta vez o arquivo é um script: uma lista de comandos do terminal (Bash) guardada num arquivo.

  2. Passo 2 Copie o script abaixo e cole no nano:
    Código de replicas.sh · copie e cole no nano
    #!/bin/bash
# Tres copias (A, B e C) da mesma informacao, em tres arquivos.
modo=$1
texto=$2

if [ "$modo" = "iniciar" ]; then
    for r in A B C; do echo "foto antiga" > replica_$r.txt; done
    echo "As tres replicas comecam iguais."

elif [ "$modo" = "eventual" ]; then
    echo "$texto" > replica_A.txt
    echo "Gravei em A e ja respondi ao cliente."
    ( sleep 5; echo "$texto" > replica_B.txt
      sleep 5; echo "$texto" > replica_C.txt ) > /dev/null 2>&1 &

elif [ "$modo" = "forte" ]; then
    exec 9> replicas.lock
    flock 9                       # LOCK: ninguem le durante a escrita
    for r in A B C; do
        echo "$texto" > replica_$r.txt
        sleep 1                   # atraso da rede, simulado
    done
    echo "Gravei em A, B e C. So agora respondo ao cliente."

elif [ "$modo" = "ler" ]; then
    exec 9> replicas.lock
    flock -s 9                    # espera se houver escrita forte
    for r in A B C; do echo "Replica $r: $(cat replica_$r.txt)"; done

else
    echo "Uso: ./replicas.sh iniciar | eventual TEXTO | forte TEXTO | ler"
fi
# fim do script
  3. Passo 3 Salve e saia: Ctrl+O, depois Enter, depois Ctrl+X.

O script, por partes:

LinhasModoO que faz
6–8iniciarGrava “foto antiga” nas três réplicas.
10–14eventualGrava só em A e responde na hora. Em segundo plano (&), a atualização chega a B depois de 5 s e a C depois de mais 5 s.
16–23fortePega a trava (flock), grava em A, B e C, com 1 s de “rede” em cada, e só então responde.
25–28lerMostra as três réplicas. Se houver uma escrita forte em andamento, espera a trava ser solta.

Etapa B · Execução

  1. Passo 4

    O que faz: sem essa permissão, o Linux não deixa rodar o arquivo como programa.

  2. Passo 5
    ./replicas.sh iniciar   # três réplicas iguais
    Saída esperada
    As tres replicas comecam iguais.
  3. Passo 6
    ./replicas.sh eventual "foto nova"; ./replicas.sh ler   # grava e já lê

    O que faz: o ; separa dois comandos na mesma linha: primeiro grava “foto nova” no modo eventual, logo em seguida lê as três réplicas.

    Saída esperada

Replica A: foto nova
Replica B: foto antiga
Replica C: foto antiga

    Observe: o cliente já recebeu a resposta, mas quem ler em B ou C ainda vê a foto antiga.

  4. Passo 7
    sleep 12; ./replicas.sh ler   # espera 12 s e lê de novo

    O que faz: não faz nada por 12 segundos (o cursor volta sozinho) e lê de novo.

    Saída esperada
    Replica A: foto nova
Replica B: foto nova
Replica C: foto nova

    Observe: as cópias convergiram: agora todas concordam.

  5. Passo 8
    time ./replicas.sh forte "foto 3"   # grava em todas antes de responder
    Exemplo medido no LIAC · os seus números mudam
    Gravei em A, B e C. So agora respondo ao cliente.

real    0m3,006s
user    0m0,002s
sys     0m0,004s

    Observe: o cliente esperou cerca de 3 s pela resposta, mas, quando ela chegou, as três cópias já eram iguais.

  6. Passo 9
    ./replicas.sh forte "foto 4" & sleep 0.5; time ./replicas.sh ler   # lê DURANTE uma escrita forte

    O que faz: começa uma escrita forte em segundo plano e, meio segundo depois, tenta ler, medindo quanto a leitura demora.

    Exemplo medido no LIAC · os seus números mudam

Gravei em A, B e C. So agora respondo ao cliente.
Replica A: foto 4
Replica B: foto 4
Replica C: foto 4
[1]+  Concluído              ./replicas.sh forte "foto 4"

real    0m2,521s
user    0m0,005s
sys     0m0,011s

    Observe: a leitura esperou a escrita terminar e não viu nenhuma mistura de “foto 3” com “foto 4”. A linha Concluído só avisa que a escrita em segundo plano terminou.

Parte 4 · cerca de 10 min Síntese

Diagnóstico

Objetivo: usar o que você mediu para decidir o que cada sistema real precisa. Não há comandos nesta parte.

Na Parte 2, a trava custou tempo e garantiu o resultado certo. Na Parte 3, o modo eventual respondeu na hora, mas mostrou cópias diferentes por alguns segundos, e o modo forte fez o contrário. Sistemas reais escolhem um lado conforme o estrago que um valor errado causaria (slide 12).

  1. Venda de ingressos numerados para um show: duas pessoas clicam na mesma cadeira.
  2. Contador de curtidas de uma postagem muito popular.
  3. Transferência PIX de uma conta conjunta, feita pelos dois titulares ao mesmo tempo.
  4. O site da universidade mudou de servidor e o DNS (o “catálogo” que traduz nomes em endereços) demora algumas horas para mostrar o endereço novo em todo lugar.
  5. Prontuário médico: uma alergia acabou de ser registrada e outro médico vai prescrever um remédio.
