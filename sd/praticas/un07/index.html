Uma estação, vários nós

Leituras didáticas: 12, 18, 24 e 30; total 84 e média 21. O mesmo serviço de AOC e SO agora é investigado por suas fronteiras de comunicação, ordem de eventos e hipóteses de falha. Os participantes dos modelos não são máquinas reais.

Ciclo de trabalho: prever → executar → interpretar → mudar uma condição → registrar uma decisão. Guarde trechos de saída acompanhados de explicação; eles serão retomados no dossiê final. Um modelo em C continua sendo um modelo, mesmo quando produz resultados exatos.

Prepare sua pasta

Use sua conta pessoal no terminal Linux. Faça a prática indicada pelo professor. Cole um bloco por vez; as pastas são independentes por unidade. O bloco do programa cria ou substitui somente o fonte com o nome indicado. Recompile se editar o código. Não é necessário Python para estas atividades.

Execute no terminal

cd ~/atividades/sd-estacao/un07
pwd
command -v bash gcc

Confira o caminho e a presença do GCC. Se faltar uma ferramenta ou fork/pipe forem bloqueados, registre a mensagem e avise o professor; use a saída docente identificada como análise documental. Download no celular não transfere arquivos ao terminal. Não há instalação com sudo, acesso à conta de colegas ou necessidade de rede no núcleo das práticas.

P07

P07 · Máquina de estados didática do 2PC

Preparar equivale a confirmar?

Base conceitual: Material da unidade 7 (PDF, nova aba). Tempo de referência: 60–90 min, ajustável pelo professor.

Duas partes do serviço devem incorporar o mesmo lote adicional +12. A estação exige tudo ou nada na confirmação: compare votos, decisão e valor visível. Cada participante começa em 84.

Programa C fornecido · abra, leia e copie

A infraestrutura está pronta. Antes de executar, localize as operações destacadas na explicação da prática. O bloco abaixo escreve o fonte e compila com C11, avisos e sem otimização.

Criar e compilar transacao.c
cat > transacao.c <<'FIM'
#include <stdio.h>
#include <string.h>

typedef enum { INICIAL, PREPARADO, CONFIRMADO, ABORTADO } Estado;
int main(int argc, char **argv) {
    const char *modo = argc == 2 ? argv[1] : "sim";
    if (argc > 2 || (strcmp(modo, "sim") && strcmp(modo, "nao") && strcmp(modo, "falha"))) {
        fputs("Uso: ./transacao [sim|nao|falha]\n", stderr); return 2;
    }
    Estado estado[] = {INICIAL, INICIAL}; int saldo[] = {84, 84};
    int votos[] = {1, strcmp(modo, "nao") != 0};
    for (int i = 0; i < 2; ++i) {
        estado[i] = votos[i] ? PREPARADO : ABORTADO;
        printf("P%d voto=%s estado=%s saldo_visivel=%d\n", i + 1,
               votos[i] ? "SIM" : "NAO", votos[i] ? "PREPARADO" : "ABORTADO", saldo[i]);
    }
    if (strcmp(modo, "falha") == 0) {
        puts("Coordenador indisponivel antes de registrar decisao; participantes aguardam.");
        puts("Resultado=PENDENTE; nao confirmar nem abortar apenas pelo timeout.");
    } else {
        int commit = votos[0] && votos[1];
        printf("Registro modelado do coordenador=%s\n", commit ? "COMMIT" : "ABORT");
        for (int i = 0; i < 2; ++i) {
            estado[i] = commit ? CONFIRMADO : ABORTADO;
            if (estado[i] == CONFIRMADO) saldo[i] += 12;
        }
        printf("Resultado=%s\n", commit ? "CONFIRMADO" : "ABORTADO");
    }
    printf("Saldos: P1=%d P2=%d\n", saldo[0], saldo[1]);
    return 0;
}
FIM
gcc -std=c11 -O0 -Wall -Wextra -Wpedantic transacao.c -o transacao

Baixar fonte transacao.c para revisão ou preparação.

Execute no terminal
./transacao sim

Interprete o programa e a saída

O enum separa INICIAL, PREPARADO, CONFIRMADO e ABORTADO. A primeira fase coleta votos; a segunda aplica uma decisão única. A alteração só é incorporada quando o estado passa a CONFIRMADO. O cenário falha interrompe o protocolo antes do registro da decisão. O observador do modelo sabe onde ocorreu a falha; os participantes preparados não podem inferir uma decisão apenas porque não recebem resposta.

Mudança orientada

Primeiro mude o voto de P2 para NÃO. Depois retorne aos votos SIM e interrompa o coordenador com falha. Compare os dois cenários separadamente com o caso original.

Executar mudança orientada
./transacao nao
./transacao falha
Referência para comparação · abra depois de prever
nao: Resultado=ABORTADO; Saldos: P1=84 P2=84
falha: Resultado=PENDENTE; Saldos: P1=84 P2=84
Limites da conclusão: Os registros são impressos, não gravados de forma durável. Não há banco, WAL, bloqueio real, recuperação após crash ou isolamento de transações concorrentes. O programa termina exibindo PENDENTE; o bloqueio pertence ao protocolo modelado, sem deixar processos presos no laboratório.
