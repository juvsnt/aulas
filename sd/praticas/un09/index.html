P09 · Modelo de cache de arquivo e revalidação

Qual versão do arquivo o cliente lê?

Base conceitual: Material da unidade 9 (PDF, nova aba). Tempo de referência: 60–90 min, ajustável pelo professor.

A abre o relatório de valor 84 e mantém uma cópia. B atualiza o servidor para 96. A faz nova leitura. Investigue o que a transparência de acesso esconde e o que ela não garante.

Programa C fornecido · abra, leia e copie

A infraestrutura está pronta. Antes de executar, localize as operações destacadas na explicação da prática. O bloco abaixo escreve o fonte e compila com C11, avisos e sem otimização.

Criar e compilar cache.c
cat > cache.c <<'FIM'
#include <stdio.h>
#include <string.h>

int main(int argc, char **argv) {
    int revalidar = argc == 2 && strcmp(argv[1], "revalidar") == 0;
    if (argc > 2 || (argc == 2 && !revalidar)) {
        fputs("Uso: ./cache [revalidar]\n", stderr); return 2;
    }
    int servidor = 84, versao = 1, copia = servidor, versao_copia = versao;
    printf("A abre relatorio: cache=%d versao=%d\n", copia, versao_copia);
    servidor += 12; ++versao;
    printf("B escreve no servidor: valor=%d versao=%d\n", servidor, versao);
    if (revalidar && versao_copia != versao) {
        copia = servidor; versao_copia = versao;
        puts("A consulta versao e recarrega cache.");
    }
    printf("A le: valor=%d versao=%d Atual=%s\n", copia, versao_copia,
           versao_copia == versao ? "SIM" : "NAO");
    return 0;
}
FIM
gcc -std=c11 -O0 -Wall -Wextra -Wpedantic cache.c -o cache

Baixar fonte cache.c para revisão ou preparação.

Execute no terminal
./cache
Referência para comparação · abra depois de prever
B escreve no servidor: valor=96 versao=2
A le: valor=84 versao=1 Atual=NAO

Interprete o programa e a saída

copia e versao_copia representam cache de um cliente. A escrita de B avança a versão do servidor. Com revalidar, A compara versões antes da segunda leitura e recarrega se necessário. A numeração de versões é fornecida pelo modelo. Um sistema de arquivos distribuído real possui regras próprias de cache, abertura, fechamento, falhas e concorrência.

Mudança orientada

Mude apenas a política de A para consultar a versão antes de ler novamente.

Executar mudança orientada
./cache revalidar
Referência para comparação · abra depois de prever
A consulta versao e recarrega cache.
A le: valor=96 versao=2 Atual=SIM
Limites da conclusão: Nenhum filesystem remoto é montado; não há NFS, SMB, RPC real nem escrita em arquivo. Não extrapole o resultado para todas as opções de montagem ou versões de NFS. Transparência de acesso não elimina erros ou esperas percebidas pela aplicação.

P10 · Modelo de resolução com TTL e tempo virtual

O nome mudou de destino?

Base conceitual: Material da unidade 9 (PDF, nova aba). Tempo de referência: 60–90 min, ajustável pelo professor.

O nome estável estacao/relatorio resolve inicialmente para no1. Em t=2 o serviço muda para no2, mas o resolvedor já guardou a resposta antiga. Consulte nos instantes virtuais 0, 3 e 11.

Programa C fornecido · abra, leia e copie

A infraestrutura está pronta. Antes de executar, localize as operações destacadas na explicação da prática. O bloco abaixo escreve o fonte e compila com C11, avisos e sem otimização.

Criar e compilar nomes.c
cat > nomes.c <<'FIM'
#include <errno.h>
#include <stdio.h>
#include <stdlib.h>

int main(int argc, char **argv) {
    int ttl = 10;
    if (argc > 2) return 2;
    if (argc == 2) {
        char *fim; errno = 0; long n = strtol(argv[1], &fim, 10);
        if (errno || !*argv[1] || *fim || n < 1 || n > 20) {
            fputs("Uso: ./nomes [ttl:1..20]\n", stderr); return 2;
        }
        ttl = (int)n;
    }
    int autoridade = 1, cache = 0, expira = 0, consultas = 0;
    const int tempos[] = {0, 3, 11};
    for (int i = 0; i < 3; ++i) {
        int t = tempos[i];
        if (i == 1) { autoridade = 2; puts("t=2 servico muda de no1 para no2."); }
        if (!cache || t >= expira) {
            cache = autoridade; expira = t + ttl; ++consultas;
            printf("t=%d consulta autoridade; ", t);
        } else printf("t=%d usa cache; ", t);
        printf("estacao/relatorio -> no%d expira=%d\n", cache, expira);
    }
    printf("Consultas=%d\n", consultas);
    puts("Resolucao de nome nao garante que o destino esteja disponivel.");
    return 0;
}
FIM
gcc -std=c11 -O0 -Wall -Wextra -Wpedantic nomes.c -o nomes

Baixar fonte nomes.c para revisão ou preparação.

Execute no terminal
./nomes 10
Referência para comparação · abra depois de prever
t=0 consulta autoridade; estacao/relatorio -> no1 expira=10
t=3 usa cache; estacao/relatorio -> no1 expira=10
t=11 consulta autoridade; estacao/relatorio -> no2 expira=21
Consultas=2

Interprete o programa e a saída

cache guarda a resposta e expira guarda seu prazo no tempo virtual. Uma consulta à autoridade renova o TTL. Quando t alcança expira, há nova resolução. O nome pode permanecer igual apesar da mudança de destino. Mesmo resolver no2 não comprova que ele responde. TTL aqui é validade temporal de cache, diferente do limite de saltos em propagação de mensagens.

Mudança orientada

Reduza apenas o TTL para 1. Mantenha migração e consultas nos mesmos instantes.

Executar mudança orientada
./nomes 1
Referência para comparação · abra depois de prever
t=0 consulta autoridade; estacao/relatorio -> no1 expira=1
t=3 consulta autoridade; estacao/relatorio -> no2 expira=4
t=11 consulta autoridade; estacao/relatorio -> no2 expira=12
Consultas=3
Limites da conclusão: Não consulta DNS nem descobre serviços de rede. Os instantes são inteiros fictícios, sem sleep. DNS real permite diferentes registros, cadeias de cache e políticas; reduzir um TTL novo não apaga retroativamente uma resposta antiga já cacheada.

P11 · Modelo de cópias de página e exclusividade

Compartilhar memória resolve a concorrência?

Base conceitual: Material da unidade 9 (PDF, nova aba). Tempo de referência: 60–90 min, ajustável pelo professor.

Dois participantes recebem cópias da página com total 84. A adiciona 12; B adiciona 18. A abstração de memória compartilhada deve coordenar visibilidade e acesso, ainda que a sintaxe da aplicação pareça local.

Programa C fornecido · abra, leia e copie

A infraestrutura está pronta. Antes de executar, localize as operações destacadas na explicação da prática. O bloco abaixo escreve o fonte e compila com C11, avisos e sem otimização.

Criar e compilar memoria.c
cat > memoria.c <<'FIM'
#include <stdio.h>
#include <string.h>

int main(int argc, char **argv) {
    int exclusiva = argc == 2 && strcmp(argv[1], "exclusiva") == 0;
    if (argc > 2 || (argc == 2 && !exclusiva)) {
        fputs("Uso: ./memoria [exclusiva]\n", stderr); return 2;
    }
    int dono = 84, a = dono, b = dono, b_valida = 1;
    puts("A e B recebem copia da pagina com total=84.");
    a += 12; dono = a;
    if (exclusiva) { b_valida = 0; puts("A obtem exclusividade; copia de B invalidada."); }
    if (!b_valida) { b = dono; b_valida = 1; puts("B busca pagina atual antes de escrever."); }
    b += 18; dono = b;
    printf("B escreve; valor no dono=%d Esperado_sem_perdas=114\n", dono);
    if (exclusiva) puts("Copia de A passa a invalida; ler exige nova consulta.");
    else puts("Ultima copia sobrescreve total: incremento de A perdido.");
    puts("Modelo sequencial de pagina; nao usa memoria remota nem mmap compartilhado.");
    return 0;
}
FIM
gcc -std=c11 -O0 -Wall -Wextra -Wpedantic memoria.c -o memoria

Baixar fonte memoria.c para revisão ou preparação.

Execute no terminal
./memoria
Referência para comparação · abra depois de prever
B escreve; valor no dono=102 Esperado_sem_perdas=114
Ultima copia sobrescreve total: incremento de A perdido.

Interprete o programa e a saída

a e b representam cópias da mesma página; dono representa a versão recebida pelo nó responsável. No modo exclusiva, a escrita de A invalida a cópia de B; antes de modificar, B busca a versão atual. O roteiro já serializa os acessos completos de A e B: a combinação de ordem exclusiva e recarga preserva os dois incrementos. Invalidação isolada, sem controlar a operação inteira, não garante esse resultado para intercalações arbitrárias.

Mudança orientada

Ative exclusiva mantendo os mesmos incrementos e a ordem de acesso do modelo.

Executar mudança orientada
./memoria exclusiva
Referência para comparação · abra depois de prever
A obtem exclusividade; copia de B invalidada.
B busca pagina atual antes de escrever.
B escreve; valor no dono=114 Esperado_sem_perdas=114
Limites da conclusão: Não usa memória remota, page fault real, mmap compartilhado ou threads. É uma sequência explícita de estados em um processo. Falso compartilhamento é uma análise da granularidade de página, sem benchmark de latência.
