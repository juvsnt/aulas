P12

P12 · Modelo de autorização e prevenção de repetição

Quem pode incorporar uma leitura?

Base conceitual: Material da unidade 10 (PDF, nova aba). Tempo de referência: 60–90 min, ajustável pelo professor.

Três pedidos chegam ao serviço: sensor01 envia +12 com sequência 1; leitor01 tenta +18; sensor01 repete a mesma sequência 1. As identidades são assumidas como autenticadas por um mecanismo externo. Investigue o que a política consegue proteger sob essa hipótese.

Programa C fornecido · abra, leia e copie

A infraestrutura está pronta. Antes de executar, localize as operações destacadas na explicação da prática. O bloco abaixo escreve o fonte e compila com C11, avisos e sem otimização.

Criar e compilar seguranca.c
cat > seguranca.c <<'FIM'
#include <stdio.h>
#include <string.h>

typedef struct { int principal, sequencia, valor; } Pedido;
int main(int argc, char **argv) {
    const char *modo = argc == 2 ? argv[1] : "aberto";
    if (argc > 2 || (strcmp(modo, "aberto") && strcmp(modo, "politica") && strcmp(modo, "replay"))) {
        fputs("Uso: ./seguranca [aberto|politica|replay]\n", stderr); return 2;
    }
    /* Identidades ja autenticadas por um mecanismo externo, nao implementado. */
    const Pedido fila[] = {{0, 1, 12}, {1, 1, 18}, {0, 1, 12}};
    const char *identidades[] = {"sensor01", "leitor01"};
    const int pode_escrever[] = {1, 0};
    int total = 84, ultima_seq[] = {0, 0};
    for (int i = 0; i < 3; ++i) {
        Pedido p = fila[i]; const char *decisao = "ACEITO";
        if (strcmp(modo, "aberto") && !pode_escrever[p.principal]) decisao = "NEGADO: papel sem escrita";
        else if (strcmp(modo, "replay") == 0 && p.sequencia <= ultima_seq[p.principal]) decisao = "NEGADO: repeticao";
        else { total += p.valor; ultima_seq[p.principal] = p.sequencia; }
        printf("%s seq=%d valor=%d %s\n", identidades[p.principal], p.sequencia, p.valor, decisao);
    }
    printf("Total=%d\n", total);
    puts("Sem criptografia, autenticacao ou canal seguro: politica sobre identidades assumidas.");
    return 0;
}
FIM
gcc -std=c11 -O0 -Wall -Wextra -Wpedantic seguranca.c -o seguranca

Baixar fonte seguranca.c para revisão ou preparação.

Execute no terminal
./seguranca aberto
Referência para comparação · abra depois de prever
sensor01 seq=1 valor=12 ACEITO
leitor01 seq=1 valor=18 ACEITO
sensor01 seq=1 valor=12 ACEITO
Total=126

Interprete o programa e a saída

pode_escrever é a política por identidade. politica aplica a autorização; replay acrescenta a comparação da sequência com a última aceita. A sequência pertence a cada principal, não é um contador único para todos. O modelo supõe ordem crescente de um único emissor, sem reinício nem mensagens legítimas reordenadas. Rejeitar sequências antigas exige uma política de sessão e persistência num serviço real. Um campo de nome enviado pelo cliente, sozinho, não é autenticação.

Mudança orientada

Ative politica e compare com aberto. Em seguida ative replay sem mudar os pedidos.

Executar mudança orientada
./seguranca politica
./seguranca replay
Referência para comparação · abra depois de prever
politica: leitor01 NEGADO; Total=108
replay: leitor01 NEGADO; repeticao NEGADA; Total=96
Limites da conclusão: Não há criptografia, autenticação real, TLS, assinatura, certificado ou armazenamento durável. Não enviar credenciais reais nem testar contas alheias. Proteger contra replay depende de vincular a sequência e o conteúdo à identidade autenticada; não basta acrescentar um contador em texto não confiável.
