P08

P08 · Modelo de omissão de resposta, retry e deduplicação

Repetir duplica o efeito?

Base conceitual: Material da unidade 8 (PDF, nova aba). Tempo de referência: 60–90 min, ajustável pelo professor.

O serviço incorpora a requisição P1:5, de valor 12, mas sua resposta não chega ao cliente. O cliente tenta novamente com o mesmo identificador. Investigue o que ele sabe e o que o servidor precisa lembrar.

Programa C fornecido · abra, leia e copie

A infraestrutura está pronta. Antes de executar, localize as operações destacadas na explicação da prática. O bloco abaixo escreve o fonte e compila com C11, avisos e sem otimização.

Criar e compilar repeticao.c
cat > repeticao.c <<'FIM'
#include <stdio.h>
#include <string.h>

int main(int argc, char **argv) {
    const char *modo = argc == 2 ? argv[1] : "sem";
    if (argc > 2 || (strcmp(modo, "sem") && strcmp(modo, "dedup") && strcmp(modo, "reinicio"))) {
        fputs("Uso: ./repeticao [sem|dedup|reinicio]\n", stderr); return 2;
    }
    int dedup = strcmp(modo, "sem") != 0;
    int total = 84, visto = 0, resposta = 0, efeitos = 0;
    for (int tentativa = 1; tentativa <= 2; ++tentativa) {
        if (tentativa == 2 && strcmp(modo, "reinicio") == 0) {
            visto = 0; puts("Reinicio modelado: efeito preservado, tabela volatil perdida.");
        }
        printf("Recebe id=P1:5 valor=12 tentativa=%d\n", tentativa);
        if (dedup && visto) puts("Duplicata: devolve resposta armazenada sem reaplicar.");
        else { total += 12; ++efeitos; visto = 1; resposta = total; }
        if (tentativa == 1) puts("Resposta suprimida: cliente observa timeout, causa desconhecida.");
        else printf("Cliente recebe resposta=%d\n", resposta);
    }
    printf("Total=%d Efeitos=%d\n", total, efeitos);
    return 0;
}
FIM
gcc -std=c11 -O0 -Wall -Wextra -Wpedantic repeticao.c -o repeticao

Baixar fonte repeticao.c para revisão ou preparação.

Execute no terminal
./repeticao sem
Referência para comparação · abra depois de prever

Interprete o programa e a saída

O primeiro efeito acontece antes da omissão da resposta. O modo dedup registra o identificador e a resposta e, na repetição, devolve a resposta anterior sem reaplicar o incremento. reinicio mantém o efeito, mas apaga a tabela volátil entre as tentativas. O cliente não distingue lentidão, resposta perdida e queda apenas pelo timeout; aqui o observador conhece a falha injetada.

Mudança orientada

Ative dedup mantendo a mesma sequência de duas tentativas. Depois use reinicio para perder apenas a tabela de identificadores, preservando o efeito já aplicado.

Executar mudança orientada
./repeticao dedup
./repeticao reinicio
Referência para comparação · abra depois de prever
dedup: Cliente recebe resposta=96; Total=96 Efeitos=1
reinicio: Cliente recebe resposta=108; Total=108 Efeitos=2
Limites da conclusão: O ID é fixo e há somente duas tentativas. Não existe timeout medido, reinício real ou armazenamento atômico e durável. O caso dedup não demonstra uma garantia geral de exactly-once. Heartbeats também produzem suspeitas sob atraso, não certeza universal de queda.
