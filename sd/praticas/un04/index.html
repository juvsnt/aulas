P04

P04 · Modelo de token e seleção de líder

Quem tem permissão para atualizar?

Base conceitual: Material da unidade 4 (PDF, nova aba). Tempo de referência: 60–90 min, ajustável pelo professor.

Três participantes querem atualizar o relatório. Um único token circula no anel P1 → P2 → P3 → P1. Investigue o que preserva o acesso exclusivo e o que permite continuar após uma falha.

Programa C fornecido · abra, leia e copie

A infraestrutura está pronta. Antes de executar, localize as operações destacadas na explicação da prática. O bloco abaixo escreve o fonte e compila com C11, avisos e sem otimização.

Criar e compilar coordenacao.c
cat > coordenacao.c <<'FIM'
#include <stdio.h>
#include <string.h>

int main(int argc, char **argv) {
    int falha = argc == 2 && strcmp(argv[1], "falha") == 0;
    if (argc > 2 || (argc == 2 && !falha)) {
        fputs("Uso: ./coordenacao [falha]\n", stderr); return 2;
    }
    int titular = 1, vivo[] = {0, 1, 1, 1}, atualizacoes = 0;
    for (int rodada = 1; rodada <= 6; ++rodada) {
        if (falha && rodada == 2) vivo[2] = 0;
        if (!vivo[titular]) {
            printf("Rodada=%d token com P%d indisponivel: sem progresso\n", rodada, titular);
            continue;
        }
        printf("Rodada=%d P%d entra, atualiza e sai; passa token\n", rodada, titular);
        ++atualizacoes; titular = titular % 3 + 1;
    }
    printf("Atualizacoes=%d; um unico titular por rodada neste modelo\n", atualizacoes);
    int eleito = 0;
    for (int i = 1; i <= 3; ++i) if (vivo[i]) eleito = i;
    printf("Selecao com visao unica: maior id vivo=P%d\n", eleito);
    puts("Visoes divergentes: {P1,P2} escolhe P2; {P3} escolhe P3.");
    puts("Escolher lider nao revoga automaticamente um token antigo.");
    return 0;
}
FIM
gcc -std=c11 -O0 -Wall -Wextra -Wpedantic coordenacao.c -o coordenacao

Baixar fonte coordenacao.c para revisão ou preparação.

Execute no terminal
./coordenacao
Referência para comparação · abra depois de prever
Atualizacoes=6; um unico titular por rodada neste modelo
Selecao com visao unica: maior id vivo=P3

Interprete o programa e a saída

titular guarda o único token do modelo e o laço concede uma entrada por rodada. vivo descreve uma falha conhecida pelo simulador. A escolha do maior id percorre uma visão única dos membros; não implementa mensagens de eleição em anel nem Bully. As duas visões impressas ao final mostram que aplicar a mesma regra sobre membros diferentes pode produzir dois líderes. Um algoritmo distribuído precisa tratar descoberta, mensagens atrasadas e autoridade antiga.

Mudança orientada

Execute o cenário falha: apenas P2 deixa de estar disponível antes da segunda rodada. Mantenha seis rodadas e não acrescente token de recuperação. Preveja quantas atualizações ocorrerão.

Executar mudança orientada
./coordenacao falha
Referência para comparação · abra depois de prever
Rodada=2 token com P2 indisponivel: sem progresso
Atualizacoes=1; um unico titular por rodada neste modelo
Selecao com visao unica: maior id vivo=P3
Limites da conclusão: O programa é sequencial e ilustra um invariante, sem provar correção para todos os escalonamentos. A falha é injetada e conhecida; timeout em rede só levantaria suspeita. Não implementa consenso, eleição completa ou recuperação segura do token.
