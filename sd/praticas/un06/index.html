P06

P06 · Modelo de escritas concorrentes e reconciliação

Convergir é suficiente?

Base conceitual: Material da unidade 6 (PDF, nova aba). Tempo de referência: 60–90 min, ajustável pelo professor.

Duas réplicas partem de total 84. Sem comunicação entre elas nesse intervalo, A incorpora +12 e B incorpora +18. A intenção é preservar ambos os incrementos, chegando a 114.

Programa C fornecido · abra, leia e copie

A infraestrutura está pronta. Antes de executar, localize as operações destacadas na explicação da prática. O bloco abaixo escreve o fonte e compila com C11, avisos e sem otimização.

Criar e compilar replicas.c
cat > replicas.c <<'FIM'
#include <stdio.h>
#include <string.h>

int main(int argc, char **argv) {
    int soma = argc == 2 && strcmp(argv[1], "soma") == 0;
    if (argc > 2 || (argc == 2 && !soma)) {
        fputs("Uso: ./replicas [soma]\n", stderr); return 2;
    }
    int a = 84, b = 84;
    puts("Inicio: A=84 B=84; cada cliente le sua replica.");
    a += 12; b += 18;
    printf("Apos escritas isoladas: A=%d B=%d\n", a, b);
    if (soma) {
        /* Componentes por produtor; merge por maximo, nao soma de totais. */
        int va[] = {12, 0}, vb[] = {0, 18};
        for (int i = 0; i < 2; ++i) {
            int maior = va[i] > vb[i] ? va[i] : vb[i];
            va[i] = maior; vb[i] = maior;
        }
        a = 84 + va[0] + va[1]; b = 84 + vb[0] + vb[1];
        puts("Merge por componente de incremento; mesmo merge repetido.");
        for (int i = 0; i < 2; ++i) if (vb[i] > va[i]) va[i] = vb[i];
        a = 84 + va[0] + va[1];
    } else {
        /* Regra declarada: escrita B vence o empate de versao. */
        a = b;
        puts("Conflito: B vence por id; incremento de A nao foi preservado.");
    }
    printf("Reconciliadas: A=%d B=%d Esperado_sem_perdas=114\n", a, b);
    puts("Convergir nao implica preservar a intencao de todas as escritas.");
    return 0;
}
FIM
gcc -std=c11 -O0 -Wall -Wextra -Wpedantic replicas.c -o replicas

Baixar fonte replicas.c para revisão ou preparação.

Execute no terminal
./replicas
Referência para comparação · abra depois de prever
Apos escritas isoladas: A=96 B=102
Reconciliadas: A=102 B=102 Esperado_sem_perdas=114

Interprete o programa e a saída

O modo padrão aplica uma regra explícita: B vence o empate de versão por identificador. A convergência pode ocorrer mesmo perdendo a intenção de A. No modo soma, cada produtor possui seu componente de incremento; o merge usa máximo por componente, e só depois calcula 84 + componentes. Não some totais de réplicas, pois isso contaria o estado inicial mais de uma vez. As leituras locais durante o intervalo continuam divergentes.

Mudança orientada

Troque apenas a regra de reconciliação por soma. Observe no código a reaplicação do mesmo merge e preveja se ela duplicará os incrementos.

Executar mudança orientada
./replicas soma
Referência para comparação · abra depois de prever
Apos escritas isoladas: A=96 B=102
Reconciliadas: A=114 B=114 Esperado_sem_perdas=114
Limites da conclusão: Incrementos são não negativos, com um produtor por componente e conjunto fixo de produtores. O exemplo é um modelo pequeno de contador convergente, sem persistência, rede ou prova de linearizabilidade. Não generalize essa reconciliação para qualquer tipo de dado nem confunda consistência de réplicas com invariantes de uma aplicação.
