Parte 1 · cerca de 10 min Medição real

Como o SO enxerga os dispositivos

Objetivo: ver que, para o Linux, cada dispositivo aparece como um arquivo especial em /dev, de bloco ou de caractere.

Dispositivo de bloco
Lê e grava em blocos de tamanho fixo, com endereço: dá para pedir “o bloco 4096”. Ex.: SSD, HD, pendrive. t01, slide 4
Dispositivo de caractere
Entrega um fluxo de bytes em sequência, sem endereço. Ex.: teclado, mouse, terminal. t01, slide 4
Driver e controlador
O driver é o software do SO que sabe falar com o controlador, o chip que comanda o dispositivo físico. t01, slide 5
  1. Passo 1
    mkdir -p ~/atividades/so-dispositivos   # cria a pasta da prática

    O que faz: cria a pasta so-dispositivos dentro da sua pasta pessoal (~).

  2. Passo 2
    cd ~/atividades/so-dispositivos   # entra na pasta da prática

    O que faz: todas as próximas partes acontecem nesta pasta.

  3. Passo 3
    ls -l /dev/null /dev/zero /dev/tty   # três dispositivos de caractere

    O que faz: lista três arquivos especiais: /dev/null (descarta tudo), /dev/zero (só entrega zeros) e /dev/tty (o seu terminal).

    Exemplo medido no computador do professor
    crw-rw-rw- 1 root root 1, 3 Nov 24 16:04 /dev/null
crw-rw-rw- 1 root tty  5, 0 Nov 24 16:04 /dev/tty
crw-rw-rw- 1 root root 1, 5 Nov 24 16:04 /dev/zero

    Observe: a primeira letra é c, de character (caractere). Onde um arquivo comum mostra o tamanho, aparecem dois números: o primeiro indica qual driver atende o dispositivo.

  4. Passo 4
    ls -l /dev | grep '^b'   # só os dispositivos de bloco

    O que faz: lista tudo em /dev e o grep '^b' mostra só as linhas que começam com b, de block (bloco).

    Exemplo medido no LIAC (trecho)
    brw-rw----   1 root disk      7,     0 nov 16 16:10 loop0
brw-rw----   1 root disk      7,     1 nov 16 16:10 loop1
brw-rw----   1 root disk      8,     0 nov 16 16:10 sda
brw-rw----   1 root disk      8,     1 nov 16 16:45 sda1
brw-rw----   1 root disk      8,     2 nov 16 16:45 sda2
brw-rw----   1 root disk      8,    16 nov 16 16:10 sdb
brw-rw----   1 root disk      8,    17 nov 16 16:45 sdb1
brw-rw----   1 root disk      8,    18 nov 16 16:45 sdb2

    Observe: sda e sdb são os discos; sda1, sdb2 etc. são partições deles. Os loop são discos virtuais feitos a partir de arquivos. Repare no primeiro número: todos os discos e partições têm 8, porque são atendidos pelo mesmo driver de disco; os loop têm 7, outro driver.

  5. Passo 5
    lsblk -d -e 7 -o NAME,TYPE,SIZE,ROTA   # discos que o kernel reconhece

    O que faz: lsblk mostra os dispositivos de bloco; -d mostra só os discos (sem as partições); -e 7 esconde os loop; -o escolhe as colunas.

    Exemplo medido no LIAC
    NAME TYPE   SIZE ROTA
sda  disk 931,5G    1
sdb  disk 931,5G    1

    Observe: a coluna ROTA diz como o kernel enxerga o disco: 1 = gira (HD mecânico), 0 = não gira (SSD). No LIAC, os dois discos são HDs mecânicos. Se o cabeçalho aparecer quebrado em duas linhas, não tem problema: é só a forma como o terminal desenhou o texto.

Parte 2 · cerca de 20 min Simulação + medição real

Polling ou interrupção?

Objetivo: medir quanto de CPU se gasta esperando um dispositivo de dois jeitos diferentes. O programa simula um “dispositivo” que fica pronto em 2 segundos: ele não conversa com um hardware de verdade. O trabalho tem três etapas: código, compilação e execução.

Polling (espera ativa)
A CPU pergunta sem parar “Pronto?” ao registrador de status, gastando ciclos enquanto espera. t02, slide 3
Interrupção (IRQ)
A CPU faz outra coisa; quando o trabalho termina, o hardware avisa com um sinal elétrico e o SO acorda quem esperava. t02, slide 4

Etapa A · Código

  1. Passo 1
    nano -l espera.c   # abre o editor nano, com números de linha

    O que faz: abre o editor nano num arquivo novo, espera.c.

  2. Passo 2 Copie o código abaixo e cole no nano (botão direito ou Ctrl+Shift+V):
    Código de espera.c · copie e cole no nano
    #include <stdio.h>
#include <string.h>
#include <time.h>

double agora(void) {
    struct timespec t;
    clock_gettime(CLOCK_MONOTONIC, &t);
    return t.tv_sec + t.tv_nsec / 1e9;
}

int main(int argc, char *argv[]) {
    if (argc != 2) {
        printf("use: ./espera polling  ou  ./espera interrupcao\n");
        return 1;
    }
    double pronto = agora() + 2.0;

    if (strcmp(argv[1], "polling") == 0) {
        long perguntas = 0;
        while (agora() < pronto) {
            perguntas++;
        }
        printf("polling: perguntei %ld vezes se estava pronto\n", perguntas);
    } else {
        struct timespec dois = {2, 0};
        nanosleep(&dois, NULL);
        printf("interrupcao: dormi 2 s e o kernel me acordou\n");
    }
    return 0;
}
// fim do codigo
  3. Passo 3 Salve e saia: Ctrl+O, depois Enter, depois Ctrl+X.

O código, linha por linha:

LinhaO que faz
1–3Incluem as bibliotecas de printf, de strcmp (comparar textos) e de relógio.
5–9A função agora() devolve a hora atual em segundos, com casas decimais.
12–15Se você não disser o modo (polling ou interrupcao), o programa explica como usar e termina.
16O “dispositivo” fica pronto daqui a 2 segundos.
18–23Polling: enquanto não chegou a hora, pergunta de novo e conta quantas vezes perguntou.
24–27Interrupção: o programa pede ao kernel para dormir 2 s (nanosleep). Ele sai da CPU; o relógio do hardware gera uma interrupção e o kernel o acorda.
31Comentário que marca o fim do código.

Etapa B · Compilação

  1. Passo 4
    gcc espera.c -o espera   # traduz o texto espera.c no programa espera

    Observe: se nada aparecer, compilou. Se aparecer erro, abra o nano de novo e confira o código.

Etapa C · Execução

  1. Passo 5
    time ./espera polling   # espera perguntando sem parar

    O que faz: time roda o programa e, no fim, mostra três tempos: real (o relógio da parede), user (CPU gasta no programa) e sys (CPU gasta no kernel, a pedido do programa).

    Exemplo medido no computador do professor · os seus números mudam
    polling: perguntei 58162462 vezes se estava pronto

real    0m2.002s
user    0m1.993s
sys     0m0.004s

    No terminal em português, os decimais aparecem com vírgula (0m2,002s).

    Observe: user fica quase igual a real: a CPU passou os 2 segundos inteiros perguntando.

  2. Passo 6
    time ./espera interrupcao   # espera dormindo até ser acordado
    Exemplo medido no computador do professor · os seus números mudam
    interrupcao: dormi 2 s e o kernel me acordou

real    0m2.003s
user    0m0.001s
sys     0m0.000s

    Observe: o mesmo real de 2 s, mas user perto de zero: nesse tempo a CPU ficou livre para outros programas.

As interrupções de verdade

O seu computador recebe interrupções o tempo todo (relógio, disco, rede, teclado). O kernel conta todas elas desde que o computador foi ligado.

  1. Passo 7
    grep -w intr /proc/stat | cut -d ' ' -f 2   # total de interrupções até agora

    O que faz: /proc/stat é um arquivo que o kernel gera com estatísticas; a linha intr começa com o total de interrupções. O cut mostra só esse número. Anote-o.

  2. Passo 8
    sleep 10   # espera 10 segundos

    O que faz: não faz nada por 10 segundos. O cursor volta sozinho.

  3. Passo 9
    grep -w intr /proc/stat | cut -d ' ' -f 2   # total de interrupções de novo

    Observe: o número cresceu. A diferença é quantas interrupções aconteceram em cerca de 10 segundos (os passos levam um pouco mais, por causa do tempo de copiar e colar).

Parte 3 · cerca de 15 min Medição real

Buffer e cache na memória

Objetivo: medir a diferença entre gravar e ler passando pela memória (RAM) do SO e indo direto ao disco.

Os arquivos são pequenos (10 MiB) porque cada conta tem uma cota, um limite de espaço no disco do servidor.

Buffer
Área da RAM que acomoda dados em trânsito entre quem produz e quem consome, compensando a diferença de velocidade. t02, slide 7
Cache
Cópia, na RAM, de dados já lidos do disco. Se o dado está lá (cache hit), não é preciso ir ao disco. t02, slide 8
Buff/cache do Linux
O Linux usa a mesma área da RAM para os dois papéis; o comando sync força a gravação no disco do que ainda está só na memória. t02, slide 12
  1. Passo 1
    free -m   # como a RAM está sendo usada, em MiB

    Observe: a coluna buff/cache: memória que o Linux está usando como buffer e cache de disco. Ela é devolvida aos programas quando eles precisam.

  2. Passo 2
    dd if=/dev/zero of=dados bs=1M count=10   # grava 10 MiB passando pelo buffer

    O que faz: dd copia dados: lê de if (input file, aqui /dev/zero) e grava em of (output file, o arquivo dados), em 10 pedaços (count) de 1 MiB (bs). No fim, mostra o tempo e a velocidade.

    Observe: a velocidade na última linha (MB/s ou GB/s). O dd termina quando os dados chegam ao buffer na RAM; o kernel grava no disco depois.

  3. Passo 3
    dd if=/dev/zero of=dados_sync bs=1M count=10 oflag=dsync   # grava esperando o disco

    O que faz: a mesma gravação, mas oflag=dsync obriga a esperar cada pedaço chegar ao disco antes de mandar o próximo.

    Observe: compare a velocidade com a do passo 2.

  4. Passo 4
    dd if=dados of=/dev/null bs=1M   # lê o arquivo, que já está no cache

    O que faz: lê o arquivo dados e joga fora o que leu (/dev/null). Como acabou de ser gravado, ele ainda está no cache.

  5. Passo 5
    dd if=dados of=/dev/null bs=1M iflag=direct   # lê ignorando o cache, direto do disco

    O que faz: iflag=direct pede ao kernel para não usar o cache: os dados vêm do disco.

    Última linha de cada dd, medida no LIAC · os seus números mudam
    passo 2:  10485760 bytes (10 MB, 10 MiB) copied, 0,00272082 s, 3,9 GB/s
passo 3:  10485760 bytes (10 MB, 10 MiB) copied, 0,409038 s, 25,6 MB/s
passo 4:  10485760 bytes (10 MB, 10 MiB) copied, 0,00107442 s, 9,8 GB/s
passo 5:  10485760 bytes (10 MB, 10 MiB) copied, 0,0725569 s, 145 MB/s

    Observe: no exemplo, gravar pelo buffer foi cerca de 150 vezes mais rápido que esperar o disco (3,9 GB/s × 25,6 MB/s), e ler do cache, cerca de 68 vezes mais rápido que ler do disco (9,8 GB/s × 145 MB/s). Lembre: 1 GB/s = 1.000 MB/s. Num servidor compartilhado os números variam, porque outras pessoas usam o mesmo disco ao mesmo tempo.

  6. Passo 6
    rm dados dados_sync   # apaga os arquivos de teste

    O que faz: apaga os 20 MiB de teste, para não ocupar a sua cota de disco à toa.

Parte 4 · cerca de 15 min Síntese

Juntando as peças

Objetivo: usar o que você mediu para explicar o caminho de uma operação de E/S e escolher a técnica certa para cada dispositivo. Esta parte não usa o terminal.

O ciclo de uma leitura
Aplicação → SO → driver → controlador → dispositivo, e a volta pelo registrador de status. t01, slide 9
DMA (acesso direto à memória)
O controlador copia um bloco inteiro direto para a RAM e só interrompe a CPU no fim. A CPU configura no início e trata a interrupção no fim. t02, slide 5
Spooling
Fila de trabalhos inteiros, guardada em disco, para um dispositivo que só atende um de cada vez, como a impressora. t02, slide 9

Se algo der errado

Aparece um ~ a mais no fim do comando colado: não tem problema; ele fica dentro do comentário e é ignorado.

“Arquivo ou diretório inexistente”: rode cd ~/atividades/so-dispositivos e tente de novo.

O nano não salvou: abra com nano -l espera.c, confira o código, Ctrl+O, Enter, Ctrl+X.

Erro ao compilar: o código foi colado pela metade. Abra o nano, apague tudo e cole de novo.

O programa não termina: aperte Ctrl+C e confira se escreveu polling ou interrupcao (sem acento).

“Cota de disco excedida”: a sua conta chegou ao limite de espaço. Rode rm dados dados_sync e du -sh ~ (quanto você está usando) e avise o professor.

dd com erro em iflag=direct: copie a mensagem na resposta e avise o professor.
