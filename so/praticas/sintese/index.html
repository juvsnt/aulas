O mesmo serviço, cinco perspectivas

Um serviço do LIAC lê quatro valores, calcula um total e escreve um relatório. O problema acompanha as investigações de kernel, processos, memória, arquivos e E/S. Os dados são didáticos; não há sensor conectado.

Use C11 e GCC no Linux. Bash organiza arquivos e executa comandos; não é necessário Python. As rotinas de apoio são fornecidas: explique as operações relacionadas a SO, sem precisar dominar toda a implementação. Recompile sempre que modificar um fonte.

O planejamento anterior reserva uma hora de laboratório por encontro. Cada P abaixo é um bloco de 60 minutos: 5 para prever, 35 para executar, 15 para interpretar e modificar e 5 para registrar. Em cada unidade, faça apenas a prática indicada pelo professor naquele encontro.

P14 · encontro de 60 minutos · Execução real e síntese de evidências

Defenda um diagnóstico integrado

Reúna as respostas P01–P13. Você vai explicar como o SO atende um programa, justificar duas decisões e reconhecer o que permaneceu fora da observação. O programa abaixo é o mesmo serviço da P02 e pode ser executado nesta pasta sem copiar arquivos de outra unidade.

Execute no terminal
printf '12 18 24 30\n' > leituras.txt

Cole o bloco inteiro. A linha FIM, sozinha, encerra a gravação. O fonte fica na pasta atual; repetir o bloco substitui somente esse arquivo do exercício.

Criar servico.c
cat > servico.c <<'FIM'
#define _POSIX_C_SOURCE 200809L
#include <stdio.h>
#include <unistd.h>
#include <errno.h>
#include <string.h>
/* API de biblioteca; o rastreamento das syscalls e uma etapa separada. */
int main(void) {
    FILE *entrada = fopen("leituras.txt", "r");
    if (!entrada) { perror("leituras.txt"); return 1; }
    int n, total = 0, quantidade = 0;
    while (fscanf(entrada, "%d", &n) == 1) {
        if (quantidade == 4 || n < -1000 || n > 1000) {
            fclose(entrada); fputs("Use exatamente quatro leituras de -1000 a 1000.\n", stderr); return 1;
        }
        total += n; quantidade++;
    }
    int ok = feof(entrada) && !ferror(entrada) && quantidade == 4;
    if (fclose(entrada)) ok = 0;
    if (!ok) { fputs("Lote invalido.\n", stderr); return 1; }
    FILE *saida = fopen("relatorio.txt", "w");
    if (!saida) { perror("relatorio.txt"); return 1; }
    ok = fprintf(saida, "Leituras=%d Total=%d\n", quantidade, total) > 0;
    if (fclose(saida)) ok = 0;
    if (!ok) return 1;
    printf("PID=%ld Leituras=%d Total=%d\n", (long)getpid(), quantidade, total);
    /* Falha controlada: descritor -1 e invalido. Nao acessa hardware. */
    errno = 0;
    ssize_t r = read(-1, &n, sizeof n);
    if (r == -1 && errno == EBADF) puts("read(-1): EBADF (descritor invalido)");
    else { fputs("Resposta inesperada ao descritor invalido.\n", stderr); return 1; }
    return 0;
}
FIM
Execute no terminal
gcc -std=c11 -O0 -Wall -Wextra -Wpedantic servico.c -o servico
./servico
Execute no terminal
cat relatorio.txt

O PID e outros dados do ambiente continuam variáveis.
Programa e arquivos → processo e threads → espaço virtual e páginas → CPU compartilhada → chamadas de sistema → sistema de arquivos → subsistemas e drivers → armazenamento

As setas organizam a explicação; não representam uma cronologia rígida. Por exemplo, carregar o programa já envolve memória e arquivos, e uma leitura pode terminar na cache. A tarefa não exige provar acesso físico ao disco. Use pelo menos uma evidência de cada unidade e identifique-a como inventário, execução ou simulação.

Mudança ou transferência: Considere um lote por minuto e depois vários produtores simultâneos. O que mudaria em processos/threads, sincronização, memória e persistência? Defenda duas decisões com as evidências; não presuma aceleração ou exija mais recursos da conta.

Se algo der errado

Ferramenta ausente: registre e avise o professor; não instale pacotes nem use sudo.

Prompt >: o shell espera o fim do bloco. Digite FIM sozinho numa linha ou interrompa com Ctrl+C e copie novamente.

Erro de compilação: confira se copiou o bloco inteiro, incluindo chaves e cabeçalhos. A compilação bem-sucedida normalmente não imprime nada; só execute após corrigir erros.

Permissão, quota ou criação de processo/thread bloqueada: registre a mensagem e use a alternativa documental ou o modelo no papel indicado pelo professor, sem contornar as políticas.

Dados variáveis: PIDs, endereços e contadores não precisam coincidir com exemplos. Não substitua os seus por números esperados.

Sem JavaScript: comandos, fontes e navegação continuam disponíveis. Responda em texto por outro meio; botões, progresso e download dependem de JavaScript.
