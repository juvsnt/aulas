Um serviço do LIAC lê quatro valores, calcula um total e escreve um relatório. O problema acompanha as investigações de kernel, processos, memória, arquivos e E/S. Os dados são didáticos; não há sensor conectado.

Use C11 e GCC no Linux. Bash organiza arquivos e executa comandos; não é necessário Python. As rotinas de apoio são fornecidas: explique as operações relacionadas a SO, sem precisar dominar toda a implementação. Recompile sempre que modificar um fonte.

O planejamento anterior reserva uma hora de laboratório por encontro. Cada P abaixo é um bloco de 60 minutos: 5 para prever, 35 para executar, 15 para interpretar e modificar e 5 para registrar. Em cada unidade, faça apenas a prática indicada pelo professor naquele encontro.

P10 · encontro de 60 minutos · Arquivos e links reais

Separe conteúdo, nome e proteção

Base conceitual da unidade: Tema 1 (PDF, nova aba) · Tema 2 (PDF, nova aba).

O relatório da estação pode ter dois nomes para o mesmo objeto ou um nome que aponta para outro caminho. Crie somente os arquivos do exercício na pasta desta unidade. As permissões experimentadas são as do próprio relatório.

Execute no terminal
umask 077
printf 'Leituras=4 Total=84\n' > relatorio.txt
if [ ! -e relatorio.hard ]; then ln relatorio.txt relatorio.hard; fi
if [ ! -L relatorio.sym ]; then ln -s relatorio.txt relatorio.sym; fi
ls -li relatorio.txt relatorio.hard relatorio.sym
stat -c '%n inode=%i links=%h bytes=%s blocos=%b' relatorio.txt relatorio.hard relatorio.sym
chmod 400 relatorio.txt
ls -l relatorio.txt
cat relatorio.hard
chmod 600 relatorio.txt

ls -i e stat permitem comparar inode e contagem de links; inclua o sistema de arquivos ao identificar um inode de modo único. O hard link deve estar no mesmo sistema de arquivos; o simbólico guarda um caminho. chmod 400 permite leitura ao proprietário; 600 também permite escrita. A permissão do objeto é compartilhada pelos hard links. As permissões dos diretórios também afetam o acesso. Em sistemas que não suportem links ou permissões POSIX, registre a restrição e faça a comparação com uma saída docente identificada como tal.

Referência para comparação · confira após prever
relatorio.txt e relatorio.hard: mesmo inode e contagem de links pelo menos 2.
relatorio.sym: objeto distinto, apontando para relatorio.txt.
Conteúdo: Leituras=4 Total=84
Inodes e blocos alocados variam.
Mudança ou transferência: Sem apagar arquivos, explique o que aconteceria com cada link se o nome relatorio.txt fosse removido, incluindo o caso de um descritor ainda aberto. Proponha permissões para um relatório privado e para um diretório compartilhado; não use chown ou contas de colegas.

P11 · encontro de 60 minutos · Modelo de alocação e inventário real

Localize os blocos sem montar um disco

Base conceitual da unidade: Tema 3 (PDF, nova aba) · Tema 4 (PDF, nova aba).

Uma imagem formatada e montada pode exigir permissões e ultrapassar a quota do LIAC. Em seu lugar, compare três organizações em um disco fictício de 12 blocos de 16 bytes. O arquivo tem 48 bytes. A alocação contígua começa no bloco 2; encadeada e indexada usam [2,7,4].

Execute no terminal
df -T .
stat -f -c 'tipo=%T bloco=%S blocos=%b livres=%f' .

Cole o bloco inteiro. A linha FIM, sozinha, encerra a gravação. O fonte fica na pasta atual; repetir o bloco substitui somente esse arquivo do exercício.

Criar alocacao.c
cat > alocacao.c <<'FIM'
#include <stdio.h>
#include <stdlib.h>
/* Disco ficticio de 12 blocos de 16 bytes; arquivo de tres blocos. */
int main(int argc,char **argv) {
    char *fim;
    long byte=argc>1?strtol(argv[1],&fim,10):25;
    if (argc>2 || (argc>1 && (fim==argv[1] || *fim)) || byte<0 || byte>47) {
        fputs("Use byte logico de 0 a 47.\n",stderr); return 1;
    }
    int bloco=(int)byte/16, offset=(int)byte%16;
    const int cadeia[]={2,7,4}, indice[]={2,7,4};
    int livres[12]; for (int i=0;i<12;i++) livres[i]=1;
    for (int i=0;i<3;i++) livres[indice[i]]=0;
    printf("byte=%ld bloco_logico=%d offset=%d\n",byte,bloco,offset);
    printf("Contigua: bloco_fisico=%d (inicio 2 + bloco logico)\n",2+bloco);
    printf("Encadeada: bloco_fisico=%d visitas_na_cadeia=%d\n",cadeia[bloco],bloco+1);
    printf("Indexada: bloco_fisico=%d entrada_do_indice=%d\n",indice[bloco],bloco);
    printf("Bitmap da organizacao indexada (1=livre): ");
    for (int i=0;i<12;i++) printf("%d",livres[i]);
    puts("\nModelo: nao le blocos fisicos, inodes ou journal reais.");
    return 0;
}
FIM
Execute no terminal
gcc -std=c11 -O0 -Wall -Wextra -Wpedantic alocacao.c -o alocacao
./alocacao 25
Execute no terminal
./alocacao 47
Referência para comparação · confira após prever
byte=25 bloco_logico=1 offset=9
Contigua: bloco_fisico=3
Encadeada: bloco_fisico=7 visitas_na_cadeia=2
Indexada: bloco_fisico=7 entrada_do_indice=1
Bitmap da organizacao indexada (1=livre): 110101101111

O bitmap apresentado descreve apenas os três blocos de dados da organização indexada; não contabiliza o armazenamento do índice ou metadados. As visitas da cadeia não equivalem a acessos físicos, pois caches podem interferir. df e stat consultam o sistema de arquivos real; os números do modelo são independentes. Journaling registra operações para recuperação de consistência; não substitui backup e não garante preservação de todo conteúdo em toda política.

Mudança ou transferência: Mude a organização indexada para [2,6,4], recompile e confira o novo bitmap e a tradução. Depois analise uma queda de energia entre reservar um bloco e atualizar o diretório: o que um journal precisaria permitir recuperar? Compare conceitualmente FAT, ext4 e NTFS sem atribuir o modelo a todos eles.

Se algo der errado

Ferramenta ausente: registre e avise o professor; não instale pacotes nem use sudo.

Prompt >: o shell espera o fim do bloco. Digite FIM sozinho numa linha ou interrompa com Ctrl+C e copie novamente.

Erro de compilação: confira se copiou o bloco inteiro, incluindo chaves e cabeçalhos. A compilação bem-sucedida normalmente não imprime nada; só execute após corrigir erros.

Permissão, quota ou criação de processo/thread bloqueada: registre a mensagem e use a alternativa documental ou o modelo no papel indicado pelo professor, sem contornar as políticas.

Dados variáveis: PIDs, endereços e contadores não precisam coincidir com exemplos. Não substitua os seus por números esperados.

Sem JavaScript: comandos, fontes e navegação continuam disponíveis. Responda em texto por outro meio; botões, progresso e download dependem de JavaScript.
