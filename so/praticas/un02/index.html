P03 · encontro de 60 minutos · Execução e observação reais

Observe e controle um processo próprio

Base conceitual da unidade: Tema 1 (PDF, nova aba) · Tema 2 (PDF, nova aba).

Um programa armazenado não é o mesmo que uma execução em andamento. Crie uma espera curta como substituto observável de um serviço bloqueado. O bloco inteiro encerra o processo, inclusive após a suspensão.

Execute no terminal
sleep 2 &
pid_lote=$!
kill -STOP "$pid_lote"
ps -p "$pid_lote" -o pid,ppid,stat,ni,comm
kill -CONT "$pid_lote"
wait "$pid_lote"
printf 'Processo acompanhado e recolhido.\n'

& inicia em segundo plano; $! guarda seu PID. STOP suspende, CONT permite continuar, e wait aguarda e recolhe a conclusão. A amostra de ps pode depender do momento; T indica parada, S espera interruptível e R executável/em execução, sem distinguir pronto de rodando. Se a conta impedir sinais ou ocultar dados, registre o bloqueio. Não envie sinais a processos de outras pessoas.

Referência para comparação · confira após prever
PID e PPID variam; PPID deve corresponder ao shell que iniciou sleep.
Processo acompanhado e recolhido.
Mudança ou transferência: Se um serviço usasse a CPU continuamente, qual transição esperaria quando fosse preemptado? Interprete a coluna NI sem supor que a prioridade garante uma fração fixa da CPU. jobs, bg e fg podem ser explorados com o professor, sem deixar trabalhos suspensos.

P04 · encontro de 60 minutos · Processos POSIX reais

Crie, substitua e recolha uma execução

Base conceitual da unidade: Tema 3 (PDF, nova aba) · Tema 4 (PDF, nova aba).

O serviço terá um filho. Ele modifica sua cópia da leitura e substitui a imagem executável com exec. O pai aguarda e confere o código de saída. Há somente um filho e ele termina sem pausas.

Cole o bloco inteiro. A linha FIM, sozinha, encerra a gravação. O fonte fica na pasta atual; repetir o bloco substitui somente esse arquivo do exercício.

Criar processos.c
cat > processos.c <<'FIM'
#define _POSIX_C_SOURCE 200809L
#include <stdio.h>
#include <string.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/wait.h>
#include <errno.h>
int main(int argc, char **argv) {
    if (argc == 2 && !strcmp(argv[1], "filho")) {
        printf("Apos exec: PID=%ld PPID=%ld\n", (long)getpid(), (long)getppid());
        return 7;
    }
    int leitura = 12;
    printf("Pai antes: PID=%ld leitura=%d\n", (long)getpid(), leitura);
    fflush(stdout); /* Nao duplicar dados pendentes do stdio no fork. */
    pid_t filho = fork();
    if (filho < 0) { perror("fork"); return 1; }
    if (filho == 0) {
        leitura = 30;
        printf("Filho antes de exec: PID=%ld PPID=%ld leitura=%d\n",
               (long)getpid(), (long)getppid(), leitura);
        fflush(stdout);
        execl("./processos", "processos", "filho", (char *)NULL);
        perror("execl"); _exit(1);
    }
    int status;
    while (waitpid(filho, &status, 0) < 0) {
        if (errno != EINTR) { perror("waitpid"); return 1; }
    }
    if (!WIFEXITED(status)) { fputs("Filho nao terminou normalmente.\n", stderr); return 1; }
    printf("Pai depois: leitura=%d codigo_filho=%d\n", leitura, WEXITSTATUS(status));
    return WEXITSTATUS(status) == 7 ? 0 : 1;
}
FIM
Execute no terminal
gcc -std=c11 -O0 -Wall -Wextra -Wpedantic processos.c -o processos
./processos
Referência para comparação · confira após prever
Pai antes: PID=<pai> leitura=12
Filho antes de exec: PID=<filho> PPID=<pai> leitura=30
Apos exec: PID=<mesmo filho> PPID=<pai>
Pai depois: leitura=12 codigo_filho=7

fork cria outro processo; os espaços de endereçamento são separados, mesmo quando há copy-on-write. execl substitui o programa do filho e preserva seu PID; não cria outro processo. waitpid recolhe seu estado de término. O 7 é um código escolhido pelo trabalhador, e o coordenador retorna sucesso ao reconhecê-lo. Sem esperar, um filho terminado pode permanecer zombie até ser recolhido; não criamos zombies persistentes neste roteiro.

Mudança ou transferência: Mude a leitura inicial para 18 e o retorno do modo filho para 9. Atualize também a verificação do pai, recompile e preveja as saídas. Compare esse isolamento com o compartilhamento entre threads da P06.

P05 · encontro de 60 minutos · Simulação determinística

Distribua a CPU entre três pedidos

Base conceitual da unidade: Tema 5 (PDF, nova aba) · Tema 6 (PDF, nova aba).

Três pedidos P1, P2 e P3 chegam no instante 0, com bursts 5, 3 e 1. O modelo tem uma CPU, sem E/S ou custo de troca. SJF não é preemptivo; RR usa quantum 2. Empates seguem a ordem dos pedidos. Isso não configura o escalonador do Linux.

Cole o bloco inteiro. A linha FIM, sozinha, encerra a gravação. O fonte fica na pasta atual; repetir o bloco substitui somente esse arquivo do exercício.

Criar escalonamento.c
cat > escalonamento.c <<'FIM'
#include <stdio.h>
#include <string.h>
/* Modelo: chegadas 0, CPU unica, sem custo de troca, quantum 2. */
int main(int argc, char **argv) {
    const char *politica = argc > 1 ? argv[1] : "fcfs";
    int rr = !strcmp(politica, "rr"), sjf = !strcmp(politica, "sjf");
    if (argc > 2 || (!rr && !sjf && strcmp(politica, "fcfs"))) {
        fputs("Use fcfs, sjf ou rr.\n", stderr); return 1;
    }
    const int burst[] = {5,3,1};
    int restante[] = {5,3,1}, fim[3] = {0}, primeira[] = {-1,-1,-1};
    int ordem[] = {0,1,2}, tempo = 0, completos = 0;
    if (sjf) { ordem[0]=2; ordem[1]=1; ordem[2]=0; }
    while (completos < 3) {
        for (int j=0; j<3; j++) {
            int p = ordem[j];
            if (!restante[p]) continue;
            int fatia = rr && restante[p] > 2 ? 2 : restante[p];
            if (primeira[p] < 0) primeira[p] = tempo;
            printf("[%d,%d) P%d\n", tempo, tempo+fatia, p+1);
            tempo += fatia; restante[p] -= fatia;
            if (!restante[p]) { fim[p]=tempo; completos++; }
        }
    }
    double espera=0, retorno=0, resposta=0;
    for (int p=0; p<3; p++) {
        int w = fim[p]-burst[p]; /* Chegadas 0; sem E/S no modelo. */
        printf("P%d espera=%d retorno=%d resposta=%d\n", p+1,w,fim[p],primeira[p]);
        espera+=w; retorno+=fim[p]; resposta+=primeira[p];
    }
    printf("Medias: espera=%.2f retorno=%.2f resposta=%.2f\n",espera/3,retorno/3,resposta/3);
    return 0;
}
FIM
Execute no terminal
gcc -std=c11 -O0 -Wall -Wextra -Wpedantic escalonamento.c -o escalonamento
./escalonamento fcfs
Execute no terminal
./escalonamento sjf
./escalonamento rr
Referência para comparação · confira após prever
FCFS: espera média=4.33; retorno médio=7.33; resposta média=4.33
SJF: espera média=1.67; retorno médio=4.67; resposta média=1.67
RR: espera média=4.33; retorno médio=7.33; resposta média=2.00

Retorno = conclusão − chegada; espera = retorno − burst neste modelo sem E/S; resposta = primeiro uso da CPU − chegada. Todos os tempos são unidades abstratas. A chegada zero torna SRTF equivalente a SJF neste cenário; não demonstra sua equivalência geral. Prioridade e filas multinível são comparações teóricas, não políticas implementadas aqui.

Mudança ou transferência: Altere somente a fatia RR de 2 para 1, recompile e compare resposta e quantidade de fatias. Depois proponha no papel chegadas não simultâneas e explique por que o programa precisaria ser ampliado para representá-las.

P06 · encontro de 60 minutos · Threads reais e interleaving controlado

Compartilhe um contador sem perder atualizações

Base conceitual da unidade: Tema 7 (PDF, nova aba) · Tema 8 (PDF, nova aba).

Duas threads confirmam um lote cada, portanto o contador deveria chegar a 2. O primeiro caso força ambas a ler antes de gravar; o segundo protege toda a operação com mutex. Usamos cargas e gravações atômicas para evitar data race e comportamento indefinido de C.

Cole o bloco inteiro. A linha FIM, sozinha, encerra a gravação. O fonte fica na pasta atual; repetir o bloco substitui somente esse arquivo do exercício.

Criar concorrencia.c
cat > concorrencia.c <<'FIM'
#define _XOPEN_SOURCE 700
#include <stdio.h>
#include <pthread.h>
#include <stdatomic.h>
/* Atomico evita data race em C; ler+somar+gravar NAO e um incremento atomico. */
static atomic_int contador;
static pthread_barrier_t barreira;
static pthread_mutex_t mutex = PTHREAD_MUTEX_INITIALIZER;
static int protegido;
static void *trabalhar(void *arg) {
    (void)arg;
    if (!protegido) {
        int copia = atomic_load(&contador);
        pthread_barrier_wait(&barreira); /* Ambos leem antes de qualquer gravacao. */
        atomic_store(&contador, copia+1);
    } else {
        pthread_mutex_lock(&mutex);
        int copia = atomic_load(&contador);
        atomic_store(&contador, copia+1);
        pthread_mutex_unlock(&mutex);
    }
    return NULL;
}
int main(void) {
    if (pthread_barrier_init(&barreira,NULL,2)) return 1;
    for (int modo=0; modo<2; modo++) {
        protegido=modo; atomic_store(&contador,0);
        pthread_t t[2];
        for (int i=0;i<2;i++) if (pthread_create(&t[i],NULL,trabalhar,NULL)) {
            fputs("Falha ao criar thread; avise o professor.\n",stderr); return 1;
        }
        for (int i=0;i<2;i++) if (pthread_join(t[i],NULL)) return 1;
        printf("%s: contador=%d esperado=2\n",modo?"Com mutex":"Atualizacao perdida",atomic_load(&contador));
    }
    pthread_barrier_destroy(&barreira); pthread_mutex_destroy(&mutex);
    return 0;
}
FIM
Execute no terminal
gcc -std=c11 -O0 -Wall -Wextra -Wpedantic -pthread concorrencia.c -o concorrencia
./concorrencia
Referência para comparação · confira após prever
Atualizacao perdida: contador=1 esperado=2
Com mutex: contador=2 esperado=2

A barreira controla a ordem para tornar a perda reproduzível; não é um conserto do incremento. O mutex envolve leitura, soma e gravação como uma única região crítica. Um contador++ comum concorrente, sem proteção, teria data race: não o usamos como experimento válido. O incremento poderia também usar uma operação read-modify-write atômica, discutida como alternativa.

Modelo de deadlock: T1 possui A e espera B; T2 possui B e espera A.

No modelo, A e B são exclusivos e não preemptíveis. Identifique exclusão mútua, posse e espera, ausência de preempção e espera circular. Proponha uma ordem global A → B para romper o ciclo. Não execute um programa que fique travado. Mutex, semáforo e monitor não são sinônimos; um semáforo pode controlar quantidade de vagas, enquanto um monitor encapsula estado e sincronização.

Mudança ou transferência: Substitua a região de leitura + soma + gravação por atomic_fetch_add(&contador, 1), removendo a barreira somente dessa variante. Preveja o resultado, recompile e explique por que essa operação difere de atomic_load seguido de atomic_store. Não coloque barreira dentro do mutex.
