O cenário do servidor

Dispositivos físicos, buffers de E/S e telemetria

A cada página que um usuário carrega, o servidor web precisa registrar uma linha no arquivo de auditoria access.log (com IP, data e status da requisição). Se o servidor fizesse uma gravação individual no disco rígido ou SSD para cada visitante, a lentidão mecânica ou a latência de barramento paralisaria a CPU. Por isso, sistemas operacionais utilizam buffers de E/S. Além disso, o Linux expõe o estado de todos os dispositivos e drivers através de interfaces em memória como /proc e /sys.

O que esta unidade permite observar

Sem buffer de stdio ainda pode haver page cache no kernel. A quantidade de writes de stdio não é fixa; uma chamada de sistema pode retornar ao mesmo processo sem troca de contexto. write e fclose não asseguram persistência imediata. Load average conta tarefas executáveis ou em espera ininterruptível, não porcentagem de CPU. Em contêineres, /proc pode expor dados do host ou restringir informações.

P12 · 60 minutos · Buffers de E/S

Gravando o access.log com e sem buffer

Crie o programa logs_buffer.c. Ele simula a gravação de 100 requisições: primeiro de forma direta sem buffer (100 chamadas write ao kernel) e depois com bufferização na memória do processo (agrupamento de escritas pela biblioteca C):

Criar logs_buffer.c
cat > logs_buffer.c <<'FIM'
#include <stdio.h>
#include <fcntl.h>
#include <unistd.h>
#include <string.h>

#define TOTAL_LOGS 100

int main(void) {
    const char *linha_log = "192.168.1.50 - GET /index.html 200 OK\n";
    size_t len = strlen(linha_log);

    printf("=== GRAVANDO %d LOGS DE ACESSO DO SERVIDOR NO DISCO ===\n", TOTAL_LOGS);

    // Metodo 1: Sem buffer da biblioteca C; o kernel ainda pode usar page cache.
    int fd_direto = open("logs_direto.txt", O_WRONLY | O_CREAT | O_TRUNC, 0644);
    if (fd_direto < 0) return 1;

    for (int i = 0; i < TOTAL_LOGS; i++) {
        if (write(fd_direto, linha_log, len) != (ssize_t)len) {
            perror("write"); close(fd_direto); return 1;
        }
    }
    close(fd_direto);

    // Metodo 2: Com buffer de E/S (dados acumulados na memoria do processo)
    FILE *f_buffer = fopen("logs_buffer.txt", "w");
    if (!f_buffer) return 1;

    for (int i = 0; i < TOTAL_LOGS; i++) {
        if (fputs(linha_log, f_buffer) == EOF) { perror("fputs"); fclose(f_buffer); return 1; }
    }
    if (fclose(f_buffer) == EOF) { perror("fclose"); return 1; }

    puts("Arquivo 'logs_direto.txt' gerado com 100 chamadas de sistema write().");
    puts("Arquivo 'logs_buffer.txt' gerado com bufferizacao eficiente da biblioteca C.");
    puts("\nConclusao de SO: Buffers podem reduzir chamadas de sistema e transicoes de modo.");

    return 0;
}
FIM
gcc -std=c11 -Wall -Wextra -O0 logs_buffer.c -o logs_buffer
./logs_buffer

Mudança orientada e evidências

Confira os arquivos com wc -l e cmp logs_direto.txt logs_buffer.txt. Troque TOTAL_LOGS para 10, recompile e compare novamente. Se strace já estiver disponível e autorizado no LIAC, use strace -c -e write ./logs_buffer; sem ele, não declare uma contagem medida para stdio.

P13 · 60 minutos · Telemetria do kernel e /proc

Painel de monitoramento do servidor em tempo real

No Linux, o diretório /proc não fica no disco: ele é um sistema de arquivos virtual com informações fornecidas pelo kernel. Inspecione a carga da CPU (load average), a memória consumida e as interrupções de hardware:

Execute no terminal
echo "=== CARGA DO SERVIDOR (1min, 5min, 15min) ==="
cat /proc/loadavg

echo "=== MEMORIA VIRTUAL E FISICA DO SERVIDOR ==="
grep -E "MemTotal|MemFree|MemAvailable|Cached|Buffers" /proc/meminfo

echo "=== INTERRUPCOES DE DISCO E REDE ATENDIDAS PELO KERNEL ==="
head -n 10 /proc/interrupts
Trecho esperado no terminal
=== CARGA DO SERVIDOR ===
0.0... 0.0... 0.0... ...
=== MEMORIA VIRTUAL E FISICA DO SERVIDOR ===
MemTotal: ... kB
MemFree:  ... kB
Cached:   ... kB
Buffers:  ... kB

Mudança orientada e evidências

Inclua MemAvailable na consulta e repita as leituras após alguns segundos. Registre o que mudou e o que permaneceu estável. Se /proc/interrupts estiver vazio ou restrito, registre essa limitação; não tente alterar permissões do sistema.
