Horda de 1.000 inimigos em processadores multicore

Divida o cálculo de uma horda de inimigos entre múltiplos núcleos da CPU e compreenda por que colocar mais núcleos não traz aceleração infinita devido à Lei de Amdahl.

Duração: 60 min Multiprocessadores, divisão de dados e limites da Lei de Amdahl

Prof. Me. Juvenal Silva Neto · Ciência da Computação

Respostas salvas automaticamente neste navegador.

O cenário do jogo

Uma batalha épica com 1.000 inimigos simultâneos

Na fase final do jogo, o herói enfrenta uma horda de 1.000 monstros na tela ao mesmo tempo. A cada quadro, a posição e a inteligência artificial de cada monstro precisam ser recalculadas. Em um processador com um único núcleo, essa carga pode derrubar o desempenho do console. Para contornar isso, os consoles modernos utilizam CPUs multicore (com 4, 8 ou mais núcleos), dividindo os monstros em lotes independentes. Mas será que ter 8 núcleos deixará o jogo 8 vezes mais rápido? A resposta está na famosa Lei de Amdahl!

02 Divisão de dados

Crie o arquivo inimigos_multicore.c para calcular o processamento dos monstros e avaliar a Lei de Amdahl:

Criar inimigos_multicore.c
cat > inimigos_multicore.c <<'FIM'
#include <stdio.h>
#include <time.h>

#define TOTAL_INIMIGOS 1000

// Funcao que calcula fisica e movimento de um intervalo de inimigos
long calcular_inimigos(int inicio, int fim) {
    long soma = 0;
    // Laco pesado para simular processamento intensivo de fisica:
    for (int rep = 0; rep < 20000; rep++) {
        for (int i = inicio; i < fim; i++) {
            soma += (i * 3 + 7) % 100;
        }
    }
    return soma;
}

int main(void) {
    printf("=== ATUALIZANDO HORDA DE %d INIMIGOS NO JOGO ===\n", TOTAL_INIMIGOS);

    // 1. Execucao sequencial (1 unico nucleo da CPU processa tudo)
    clock_t t0 = clock();
    long res_total = calcular_inimigos(0, TOTAL_INIMIGOS);
    clock_t t1 = clock();
    double tempo_1_core = (double)(t1 - t0) / CLOCKS_PER_SEC;

    printf("1 Nucleo:       Tempo = %.4f s (Resultado = %ld)\n", tempo_1_core, res_total);

    // 2. Divisao do lote para 2 Nucleos (particionamento de dados)
    // Nucleo A calcula 0 a 499; Nucleo B calcula 500 a 999
    clock_t t2 = clock();
    long loteA = calcular_inimigos(0, 500);
    long loteB = calcular_inimigos(500, 1000);
    long res_divisao = loteA + loteB;
    clock_t t3 = clock();
    double tempo_2_lotes = (double)(t3 - t2) / CLOCKS_PER_SEC;

    printf("2 Lotes de 500: Lote A = %ld | Lote B = %ld (Total = %ld)\n", loteA, loteB, res_divisao);
    printf("Tempo total medido sequencialmente: %.4f s\n", tempo_2_lotes);

    // 3. Analise teorica da Lei de Amdahl no jogo
    double p = 0.80; // 80% do tempo eh calculo de inimigos (paralelizavel)
    printf("\n=== LEI DE AMDAHL: LIMITES DE ACELERACAO DO JOGO ===\n");
    printf("Cenario: 80%% do jogo eh fisica paralelizavel e 20%% eh desenho sequencial de tela:\n");

    int cores[] = {1, 2, 4, 8, 16};
    for (int c = 0; c < 5; c++) {
        int n = cores[c];
        double aceleracao = 1.0 / ((1.0 - p) + (p / n));
        printf("Com %2d nucleos: Aceleracao maxima teorica = %.2fx\n", n, aceleracao);
    }

    double limite = 1.0 / (1.0 - p);
    printf("Com infinitos nucleos: Aceleracao maxima nunca ultrapassa %.1fx!\n", limite);

    return 0;
}
FIM

03 Particionamento

Como dividir o trabalho entre núcleos?

A técnica utilizada chama-se particionamento de dados: os 1.000 inimigos não dependem diretamente uns dos outros para calcular suas trajetórias. Assim, o Núcleo 1 processa os inimigos de índice 0 a 499, enquanto o Núcleo 2 processa simultaneamente os inimigos de 500 a 999. Ao final, a CPU apenas reúne as posições.

04 Lei de Amdahl

Por que 8 núcleos não deixam o jogo 8x mais rápido?

A Lei de Amdahl diz que a aceleração máxima obtida por computadores paralelos é estritamente limitada pela fração do programa que NÃO pode ser paralelizada (a parte sequencial).

No nosso jogo, 80% do tempo ($p = 0.80$) é o cálculo dos monstros. Mas os outros 20% do tempo ($1 - p = 0.20$) são estritamente sequenciais: atualizar o placar do jogador, tocar o som da fase e enviar o quadro para o cabo HDMI da TV. Mesmo que os monstros fossem calculados em zero segundos com infinitos núcleos, o jogo ainda levaria o tempo fixo dos 20% sequenciais. Portanto, a aceleração máxima teórica é $1 / 0.20 = \mathbf{5.0\times}$!
