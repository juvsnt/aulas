A CPU em batalha: o golpe do monstro

Acompanhe o ciclo de instrução passo a passo dentro do processador: como o Program Counter (PC), o registrador IR, a ULA e a Flag Zero decidem o Game Over.

Duração: 60 min Ciclo Busca-Decodifica-Executa, PC, IR, ULA e flags

Prof. Me. Juvenal Silva Neto · Ciência da Computação

Respostas salvas automaticamente neste navegador.

O cenário do jogo

O que acontece na CPU quando o herói toma um ataque?

Durante a batalha, o herói tem 50 pontos de vida guardados na memória RAM. Um monstro ataca e causa 50 de dano. Para processar essa regra, a CPU precisa buscar a instrução apontada pelo PC (Program Counter), decodificar a operação no IR (Instruction Register), trazer a vida para um registrador rápido, acionar a ULA (Unidade Lógica e Aritmética) para subtrair o dano e testar a Flag Zero (ZF) para saber se a vida chegou a zero e acionar o Game Over.

02 Simulador do ciclo

Execute o combate na CPU

Crie o arquivo cpu_game.c, compile e execute para ver o ciclo de instrução passo a passo:

Criar cpu_game.c
cat > cpu_game.c <<'FIM'
#include <stdio.h>
#include <string.h>

int main(void) {
    // Memoria principal (RAM): posicao 0 contem a Vida do Heroi
    int memoria[] = {50};
    int pc = 0;           // Program Counter (Aponta para a instrucao atual)
    int r0 = 0;           // Registrador de uso geral da CPU
    int zf = 0;           // Flag Zero (1 se a ultima operacao na ULA resultou em 0)

    // Programa de instrucoes da CPU para a rotina de combate:
    const char *instrucoes[] = {"LOAD", "SUB", "STORE", "JZ", "HALT"};
    int operandos[]          = { 0,     50,    0,       4,    0    };

    printf("=== CPU DO CONSOLE: CICLO DE INSTRUCAO DE COMBATE ===\n");
    printf("Vida inicial guardada na RAM[0] = %d HP\n\n", memoria[0]);

    while (1) {
        int ciclo_pc = pc;
        const char *ir = instrucoes[pc]; // 1. BUSCA: IR recebe instrucao
        int op = operandos[pc];
        pc++;                           // 2. INCREMENTO DO PC

        // 3. DECODIFICACAO E EXECUCAO (ULA e Registradores)
        if (strcmp(ir, "LOAD") == 0) {
            r0 = memoria[op];           // Carrega da RAM para o registrador R0
        } else if (strcmp(ir, "SUB") == 0) {
            r0 -= op;                   // ULA realiza a subtracao do dano
            zf = (r0 <= 0);             // Se a vida zerou, ativa Flag Zero
        } else if (strcmp(ir, "STORE") == 0) {
            memoria[op] = r0;           // Grava o novo valor de volta na RAM
        } else if (strcmp(ir, "JZ") == 0) {
            if (zf) {                   // Se flag Zero ativa, desvia o PC
                printf("  [DESVIO CONDICIONAL] Vida zerou! Desviando PC para Game Over.\n");
                pc = op;
            }
        } else if (strcmp(ir, "HALT") == 0) {
            printf("PC=%d | IR=%-5s    | Fim da execucao da CPU.\n", ciclo_pc, ir);
            break;
        }

        printf("PC=%d | IR=%-5s %2d | R0=%2d | Flag ZF=%d | RAM[0]=%d HP\n",
               ciclo_pc, ir, op, r0, zf, memoria[0]);
    }

    printf("\nResultado Final: RAM[0] = %d (Heroi derrotado)\n", memoria[0]);
    return 0;
}
FIM
gcc -std=c11 -Wall -Wextra -O0 cpu_game.c -o cpu_game
./cpu_game

03 Ciclo de instrução

Rastreando os estágios de cada ciclo

A cada repetição do laço da CPU, três coisas acontecem:

  1. Busca (Fetch): A CPU lê a instrução que está no endereço apontado por PC e guarda no registrador IR. Em seguida, o PC é incrementado para apontar para a próxima instrução.
  2. Decodificação (Decode): A CPU descobre qual circuito deve ser ativado (LOAD, SUB, STORE ou desvio).
  3. Execução (Execute): A ULA calcula ou a memória transfere dados.
04 Papel dos registradores

Por que a CPU usa registradores internos?

A memória principal (RAM) fica fora do chip do processador e é relativamente lenta. Para realizar cálculos matemáticos na ULA com velocidade máxima, a CPU precisa primeiro carregar os dados para seus registradores internos (como R0). Somente após o resultado estar pronto é que ela grava de volta na RAM (com a instrução STORE).
