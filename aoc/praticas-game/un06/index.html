O cenário do jogo

O desafio dos 60 quadros por segundo (60 FPS)

Para um jogo rodar com fluidez impecável a 60 FPS, o hardware precisa gerar um quadro novo a cada 16,6 milissegundos! Cada quadro precisa passar por 4 etapas sequenciais: E (Entrada), F (Física), C (Colisão) e R (Renderização). Se o console executasse um quadro de cada vez do início ao fim (modo sequencial), o jogo ficaria lento. A solução da arquitetura de computadores é o Pipeline: sobrepor as etapas para que, enquanto um quadro está sendo desenhado na tela, a física do próximo já esteja sendo calculada!

02 Simulador de pipeline

Crie o simulador de pipeline gráfico

Crie o arquivo pipeline_fps.c que visualiza o avanço temporal dos quadros pelos 4 estágios da CPU:

Criar pipeline_fps.c
cat > pipeline_fps.c <<'FIM'
#include <stdio.h>
#include <stdlib.h>

int main(int argc, char **argv) {
    int quadros = 6;
    int bolhas = (argc > 1) ? atoi(argv[1]) : 0;
    if (bolhas < 0 || bolhas > 3) bolhas = 0;

    int estagios = 4; // E=Entrada, F=Fisica, C=Colisao, R=Renderizacao
    int ciclos_total = quadros + (estagios - 1) + bolhas;

    printf("=== PIPELINE GRAFICO DO MOTOR DE JOGO (%d QUADROS) ===\n", quadros);
    printf("Estagios: E=Entrada | F=Fisica | C=Colisao | R=Renderizacao\n");
    if (bolhas > 0) {
        printf("Simulando %d ciclo(s) de bolha/engasgo (stall) a partir do Quadro 3!\n", bolhas);
    }
    printf("\n");

    const char nomes_estagios[] = "EFCR";

    for (int q = 0; q < quadros; q++) {
        int atraso = (q >= 2) ? bolhas : 0;
        int inicio = q + atraso;

        printf("Quadro %d: ", q + 1);
        for (int t = 0; t < ciclos_total; t++) {
            int estagio_idx = t - inicio;
            if (estagio_idx >= 0 && estagio_idx < estagios) {
                printf("%c ", nomes_estagios[estagio_idx]);
            } else {
                printf(". ");
            }
        }
        printf("\n");
    }

    printf("\n=== METRICAS DE DESEMPENHO E 60 FPS ===\n");
    int sem_pipeline = quadros * estagios;
    printf("Tempo sequencial (sem pipeline): %d ciclos\n", sem_pipeline);
    printf("Tempo com pipeline:              %d ciclos\n", ciclos_total);
    printf("Aceleracao (Speedup):            %.2fx mais rapido\n", (double)sem_pipeline / ciclos_total);
    if (bolhas > 0) {
        puts("Aviso: As bolhas causaram perda de ciclos e queda momentanea de FPS (stuttering).");
    } else {
        puts("Pipeline ideal: 60 FPS cravados e transicoes perfeitas!");
    }

    return 0;
}
FIM
gcc -std=c11 -Wall -Wextra -O0 pipeline_fps.c -o pipeline_fps

05 Desafio teórico

E se o jogo rodar por 1.000 quadros?

A latência de um único quadro continua sendo de 4 estágios. Mas quando o pipeline está cheio, sai 1 quadro pronto a cada ciclo!

Para $N = 1000$ quadros sem bolhas, o tempo com pipeline seria de apenas $1000 + (4 - 1) = 1003$ ciclos, enquanto no modo sequencial levaria $1000 \times 4 = 4000$ ciclos.
