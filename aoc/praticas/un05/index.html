02Entrada/saída, interfaces e barramentos

Localize a fronteira da observação

A estação precisa receber leituras e publicar o resultado. Não há sensor físico conectado a esta prática: um arquivo de quatro bytes representará um lote já coletado. Vamos consultar dispositivos de armazenamento sem escrever neles.

Execute no terminal
lsblk -o NAME,TYPE,SIZE,ROTA | head -n 12
ls /sys/bus/pci/devices | head -n 5

lsblk lista dispositivos e sua organização; ROTA informa se o kernel os classifica como rotacionais. /sys/bus/pci/devices lista funções PCI conhecidas do Linux. Os nomes dependem da máquina; uma função PCI não é necessariamente uma placa removível.

Se o ambiente não expuser esses dados, registre “não disponível”. Listagens não medem a largura ou a taxa efetiva de um barramento. Um arquivo não é um controlador, e o teclado do celular chega pela sessão remota, não por um cabo USB ligado ao servidor.
03Entrada/saída, interfaces e barramentos

Compare transferências pequenas e em lote

Preveja: ler um byte quatro vezes e ler quatro bytes uma vez produzirá a mesma soma? Cole o programa. Ele cria somente os arquivos locais leituras.bin e relatorio.txt.

Cole o bloco inteiro. A primeira linha inicia a gravação; a linha final FIM, sozinha, encerra. O arquivo fica nesta pasta. O símbolo > no prompt durante a colagem significa que o shell está esperando o fim do bloco.

Criar entrada_saida.c
cat > entrada_saida.c <<'FIM'
#include <stdio.h>
#include <string.h>
/* Um arquivo representa o lote ja coletado, nao o sensor fisico. */
int main(void) {
    unsigned char dados[] = {12,18,24,30}, unidades[4], lote[4];
    FILE *f = fopen("leituras.bin", "wb");
    if (!f) { perror("leituras.bin"); return 1; }
    int ok = fwrite(dados, 1, 4, f) == 4;
    if (fclose(f) != 0) ok = 0;
    if (!ok) return 1;
    f = fopen("leituras.bin", "rb");
    if (!f) return 1;
    if (setvbuf(f, NULL, _IONBF, 0)) { fclose(f); return 1; }
    for (int i = 0; i < 4; i++) {
        if (fread(&unidades[i], 1, 1, f) != 1) { fclose(f); return 1; }
    }
    if (fclose(f)) return 1;
    f = fopen("leituras.bin", "rb");
    if (!f) return 1;
    if (setvbuf(f, NULL, _IONBF, 0)) { fclose(f); return 1; }
    ok = fread(lote, 1, 4, f) == 4;
    if (fclose(f) != 0) ok = 0;
    if (!ok) return 1;
    int total = 0;
    for (int i = 0; i < 4; i++) total += lote[i];
    puts("Leituras de 1 byte: 4\nLeituras de 4 bytes: 1");
    printf("Mesmo conteudo: %s\nTotal bruto: %d\n", !memcmp(unidades,lote,4) ? "verdadeiro" : "falso", total);
    f = fopen("relatorio.txt", "w");
    if (!f) return 1;
    ok = fprintf(f, "Total bruto=%d\n", total) > 0;
    if (fclose(f) != 0) ok = 0;
    if (!ok) return 1;
    /* Modelo de custo: dispositivo pronto apos 3 consultas por byte. */
    puts("MODELO: polling: consultas=12 copias_CPU=4");
    puts("MODELO: interrupcao por byte: avisos=4 copias_CPU=4");
    puts("MODELO: DMA por lote: configuracoes=1 avisos=1 bytes=4");
    return 0;
}
FIM
Execute no terminal
gcc -std=c11 -O0 -Wall -Wextra -Wpedantic entrada_saida.c -o entrada_saida
./entrada_saida
od -An -tu1 leituras.bin
cat relatorio.txt

fopen abre o arquivo binário; setvbuf(..., _IONBF, ...) desativa o buffer da biblioteca C nesse fluxo. Quatro chamadas fread solicitam um byte cada; outra chamada solicita o lote de quatro bytes. memcmp compara os vetores; fprintf grava o relatório e fclose fecha cada arquivo.

04Entrada/saída, interfaces e barramentos

Diferencie software de transferência física

As contagens acima são de chamadas fread da biblioteca C, não de chamadas de sistema medidas. Mesmo sem buffer da biblioteca C, há outras camadas: sistema de arquivos, cache de páginas do kernel, driver, controlador e dispositivo. Uma leitura pode ser atendida em RAM e não causar nova leitura física do disco.

Arquivo → chamada de leitura → kernel/cache → buffer do programa → processamento → relatório

Se o dado não estiver em cache, o caminho pode envolver armazenamento e sua interface/controlador. Ler um lote com fread(lote, 1, 4, f) não demonstra que ocorreu uma operação DMA: a configuração do hardware é gerenciada pelo kernel e pelo driver.

05Entrada/saída, interfaces e barramentos

Compare três estratégias no modelo

O fim do programa imprime um modelo de custos com as seguintes hipóteses: quatro bytes; no polling, cada byte exige três consultas até estar pronto; no modo por interrupção, um aviso por byte; no DMA, um lote e um aviso final. Não há espera ocupada real, interrupções programadas pelo aluno ou acesso direto ao controlador.

Saída esperada · dados fixos
MODELO: polling: consultas=12 copias_CPU=4
MODELO: interrupcao por byte: avisos=4 copias_CPU=4
MODELO: DMA por lote: configuracoes=1 avisos=1 bytes=4

No polling a CPU consulta e copia. No exemplo por interrupção ela trata o aviso e ainda copia. No DMA ela configura uma transferência que o controlador conduz entre dispositivo e memória, com notificação de conclusão segundo o modelo. Essas são políticas didáticas; sistemas reais podem agrupar interrupções e adotar estratégias híbridas.

Se algo der errado

Prompt > após colar: falta o terminador do bloco. Digite FIM sozinho em uma linha, ou interrompa com Ctrl+C e copie novamente.

No such file: confira pwd e ls. O arquivo deve estar na pasta desta unidade.

Quota excedida: avise o professor; não crie arquivos grandes nem aumente o tamanho dos experimentos.

Rede ou sudo bloqueados: as atividades não precisam deles. Não tente contornar as políticas do laboratório.
