02CPU, controle e caminho de dados

Defina o estado antes da execução

Vamos seguir a leitura 24: carregar, somar o ajuste 2, guardar 26 e decidir se atingiu o limiar. O modelo possui um registrador R, posições de dados 0 e 1 e sete instruções numeradas de 0 a 6. O PC indica a próxima instrução; o IR guarda a instrução em processamento.

Cole o bloco inteiro. A primeira linha inicia a gravação; a linha final FIM, sozinha, encerra. O arquivo fica nesta pasta. O símbolo > no prompt durante a colagem significa que o shell está esperando o fim do bloco.

Criar cpu.c
cat > cpu.c <<'FIM'
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
/* Modelo: PC indexa instrucoes; dados usam enderecos 0 e 1. */
int main(int argc, char **argv) {
    char *fim;
    long valor = argc > 1 ? strtol(argv[1], &fim, 10) : 24;
    if (argc > 2 || (argc > 1 && (fim == argv[1] || *fim)) || valor < -1000 || valor > 1000) {
        fputs("Use uma leitura inteira de -1000 a 1000.\n", stderr); return 1;
    }
    int mem[] = {(int)valor, 0}, r = 0, zf = 0, cmp = 0, pc = 0;
    const char *ops[] = {"LOAD", "ADD", "STORE", "CMP", "JGE", "HALT", "HALT"};
    int args[] = {0, 2, 1, 24, 6, 0, 0};
    for (;;) {
        int atual = pc, arg = args[pc];
        const char *op = ops[pc]; /* Busca: IR recebe a instrucao no PC. */
        pc++;
        if (!strcmp(op, "LOAD")) r = mem[arg];
        else if (!strcmp(op, "ADD")) r += arg;
        else if (!strcmp(op, "STORE")) mem[arg] = r;
        else if (!strcmp(op, "CMP")) { cmp = r - arg; zf = cmp == 0; }
        else if (!strcmp(op, "JGE") && cmp >= 0) pc = arg;
        printf("PC=%d IR=%s %d R=%d ZF=%d\n", atual, op, arg, r, zf);
        printf("  proximo_PC=%d memoria[1]=%d\n", pc, mem[1]);
        if (!strcmp(op, "HALT")) break;
    }
    return 0;
}
FIM

A lista programa representa instruções e mem representa dados; a separação no código facilita a leitura e não descreve o arranjo físico de um computador. LOAD copia da memória para R, ADD soma um imediato, STORE grava R, CMP compara, JGE desvia se maior ou igual, e HALT encerra.

Este programa simula uma CPU simples. PC conta posições da lista, não bytes. Não é a microarquitetura do i7, não mede seus sinais de controle e não lê registradores reais.
03CPU, controle e caminho de dados

Acompanhe busca, decodificação e execução

Execute no terminal
gcc -std=c11 -O0 -Wall -Wextra -Wpedantic cpu.c -o cpu
./cpu 24

O argumento 24 é a leitura inicial. A cada volta, o código busca a instrução com PC, identifica seu opcode e executa a operação. Cada par de linhas é o estado depois da execução: PC identifica a instrução que acabou de ser executada e proximo_PC é o novo valor do contador.

Saída esperada · dados fixos
PC=0 IR=LOAD 0 R=24 ZF=0
  proximo_PC=1 memoria[1]=0
PC=1 IR=ADD 2 R=26 ZF=0
  proximo_PC=2 memoria[1]=0
PC=2 IR=STORE 1 R=26 ZF=0
  proximo_PC=3 memoria[1]=26
...
PC=4 IR=JGE 6 R=26 ZF=0
  proximo_PC=6 memoria[1]=26

A unidade de controle escolhe a ação pelo opcode; o caminho de dados efetua a transferência ou a soma. A ULA produz 26 antes de ele ser armazenado. Assim, memoria[1] continua 0 logo após ADD: registrador e memória não são a mesma coisa.

04CPU, controle e caminho de dados

Uma comparação muda o caminho

Agora preveja o caminho para 18 e para 22. CMP calcula internamente a diferença e define ZF quando ela é zero. O desvio usa a comparação com sinal. Na CPU real, condições de desvio podem combinar vários flags: ZF sozinho não responde “maior ou igual”.

Execute no terminal
./cpu 18
./cpu 22
Resumo a localizar nas duas execuções
Leitura 18: R final=20; ZF=0; termina em PC=5
Leitura 22: R final=24; ZF=1; termina em PC=6

O valor 22 corrigido é exatamente 24: o desvio também deve ocorrer. O endereço 5 é pulado quando a condição é verdadeira. Os dois HALT representam os caminhos “sem alerta” e “com alerta”.

Exploração opcional: registradores reais com GDB

Somente se gdb existir e a depuração da própria conta for permitida. Não mude permissões do servidor para habilitá-la. Requer ter concluído a unidade 2.

Execute no terminal
command -v gdb
cd ~/atividades/aoc-estacao/un02
gcc -O0 -g estacao.c -o estacao

Cole o bloco inteiro. A primeira linha inicia a gravação; a linha final FIM, sozinha, encerra. O arquivo fica nesta pasta. O símbolo > no prompt durante a colagem significa que o shell está esperando o fim do bloco.

Criar passos.gdb
cat > passos.gdb <<'FIM'
set pagination off
set debuginfod enabled off
set disable-randomization off
set disassembly-flavor intel
break calibrar
run
print leitura
info registers rip rbp rsp
x/i $pc
stepi
x/i $pc
FIM
Execute no terminal
gdb -q -batch -x passos.gdb ./estacao

O arquivo desliga paginação e buscas externas de símbolos, interrompe na função, imprime leitura (12 na primeira chamada), mostra RIP/RBP/RSP, exibe a próxima instrução e executa uma instrução com stepi. Os endereços e a instrução inicial variam. Se houver “ptrace: Operation not permitted”, registre a restrição e use o modelo principal. RIP é o contador de instruções x86-64; RBP/RSP são registradores usados no manejo da pilha.
